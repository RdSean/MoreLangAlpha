# 家庭教材与章节学习讨论记录

**状态：讨论中，非实施计划。**

本文记录截至 2026-08-11 已确认的产品方向，目的是让后续讨论不依赖
对话上下文。未列为“已确认”的事项仍待讨论，不应据此开始实现。

## 产品定位

家庭教育模块在现有 Flash / PTC 架构上增加可复用的教材知识资产。
家长维护教材，学生学习已发布教材的章节；教材加工由 PTC 异步完成。
这不是 RAG 产品：学生进入某章节时，系统确定性地加载该章节及其教学
材料，Agent 按正常资产访问机制读取完整内容或所需文件。

目标体验接近面向学生的项目知识浏览与问答：教材有目录、章节、知识点
和学习状态，既可浏览，也能作为学习对话的上下文。

## 家庭与权限

- 家长和学生都是独立账户，属于同一个家庭。
- 家长创建和管理学生账户，维护家庭教材库，并创建学生的教材学习入口。
- 学生不维护教材或订阅关系；学生进入被挂载的学习空间，阅读、提问、
  完成知识检查并留下学习记录。
- 家长可以查看学生的学习轨迹、检查结果和薄弱点，并维护教材与挂载关系。

## 教材库与复用

- 教材属于家庭教材库，可被多个学生、多个学习空间重复挂载，以支持交叉
  学习。
- 一本教材的规范名称由家长确认；不以首次上传的 PDF 文件名作为教材身份。
- 一个教材版本可由一次或多次上传的 PDF 组成，例如正文、分册和配套材料。
- 系统不得自动把新上传文件合并到既有教材。每次上传先成为候选版本或候选
  来源，由家长手工确认其归属与合并关系。

## 资产分层与版本规则

教材需要分层管理，而不是把所有内容混为一个 Markdown 文件。

1. **原始教材资产**：PDF、扫描页、图片、上传来源和文件哈希。原始文件不可
   覆盖；重传产生新候选来源。
2. **教材内容资产**：本地 PDF 提取、未来 Datalab 等提取器产生的目录、章节、
   页码映射和 Markdown。机器识别结果保留；家长更正时创建人工校正的内容版本，
   不覆盖原提取结果。
3. **教学知识资产**：由 `book-to-skill` 和 `the-knowledge-guy` 加工出的知识点、
   学习目标、重点难点、讲解、技巧和知识检查。该层可按学生背景或学习目标产生
   多个教学包版本，不必重新提取 PDF。
4. **已发布材料版本**：明确冻结的“教材内容版本 + 教学包版本”组合。学生学习
   空间实际挂载的是此发布版本。

家长可以调整教材内容与教学材料，但所有调整产生新版本。修改教材内容会使其
依赖的教学包标记为需要重新生成；只修改教学目标、知识点或检查题时，仅产生
新的教学包版本。

已在学习的学生空间不会自动切换新版。家长确认后，才对每一个学习空间执行
显式升级；旧版本及其学习记录继续可用。

## 存储与可恢复性

- 原 PDF、图片、提取 Markdown、人工校正 Markdown 和教学包 Markdown 使用现有
  S3 兼容对象存储（MinIO）保存。
- PostgreSQL 管理教材、版本、章节、知识点、发布状态、权限、学生挂载和学习
  记录等关系；数据库不是教材内容唯一的解释来源。
- 不把某个 PTC Workspace/sandbox 的文件系统作为教材的唯一副本。Workspace 只在
  被授权的加工或学习过程中访问所需资产。
- 正式资产路径与文件名必须可读、稳定，沿用知识技能的目录化命名习惯，不用
  随机 ID 作为 Markdown 文件名。例如：

  ```text
  家庭教材库/
    新概念英语-第二册/
      v1/
        README.md
        manifest.json
        原始资料/新概念英语-第二册-扫描版.pdf
        教材章节/01-a-private-conversation.md
        教学包-中文学习者/01-a-private-conversation-学习材料.md
        教学包-中文学习者/01-a-private-conversation-知识检查.md
  ```

- 每个教材版本目录包含人可读的 `README.md` 与机器可恢复的 `manifest.json` 或
  等价 frontmatter，记录章节顺序、页码、文件关系、依赖版本和校验信息。数据库
  丢失后，系统可扫描这些目录与清单重建索引。
- 用户界面通过经家庭与角色授权的服务端 API 浏览或下载教材，不暴露对象存储的
  公开地址。

## 家长教材库

家长端需要一个统一的教材库，而不是仅在聊天或 Workspace 文件面板中寻找材料。
每本教材至少可查看：

- 候选、加工中、待发布、已发布、已归档等状态；
- 原始资料、提取报告和版本关系；
- 章节目录、页码、可读 Markdown 与教学包；
- 该版本被哪些学生与学习空间挂载；
- PDF 页面与对应章节 Markdown 的只读并排预览，用于发布前判断提取质量。

发布是轻量的家长确认动作：不要求家长编辑内容，但学生只可访问已发布章节或
教学包，避免 OCR 错误、目录错乱或未完成加工的资料直接进入学生端。

## PTC 教材加工流程

- 家长先创建教材草稿并确认规范书名，可分多次上传 PDF、扫描件和配套资料。
- 上传文件在家长确认前只是候选来源，不自动触发昂贵的提取或教学加工。
- 家长点击“开始加工”后，PTC 创建冻结的加工任务；随后上传的文件不会悄悄
  进入该任务，只能用于新的教材版本。
- 加工阶段为：资料检查、内容提取、目录与章节结构化、教学包与默认题集生成、
  校验、待家长审阅。阶段结果和错误应保留，并支持从失败阶段重试。
- 成功加工只会产生待发布候选资产，不能覆盖已发布版本，也不能自动让学生访问。

## 学习空间与学习证据

- 一个逻辑学习空间对应“学生 × 已发布材料版本”。它可在不预设时间表的情况下
  独立保存章节上下文、对话与学习证据。
- 逻辑学习空间仅在第一次需要 PTC 深度加工或学习时懒创建实际 Workspace/sandbox，
  避免为大量尚未使用的教材入口创建闲置沙盒。
- 学生可自由进入章节。首期不要求家长设置期限、学习计划、打卡频率或作业排期。
- 每章展示明确的应掌握知识点、能力目标和必要前置知识。
- 每章保留轻量知识检查，不做强制通关。检查结果、关键问答和学生主动完成记录
  共同构成学习证据。
- 章节状态可包含未开始、学习中、已学习、完成检查和建议复习。“掌握”不能只由
  阅读时长或打开次数推断。
- 未来打印或导出应从同一份已发布章节教学快照生成，确保纸面材料与线上内容的
  知识点和检查一致。
- 学生与家长都通过独立的教材阅读器浏览目录、章节和小节，而不是只在聊天中
  查看文件。学生默认可访问学习空间所挂载教材的全部已发布章节；首期不锁章节
  或强制顺序。阅读器提供稳定章节链接，当前章节成为学习对话的默认上下文。
- 家长有学生视图和教材管理视图：前者查看学生实际看到的材料与学习状态，后者
  查看原 PDF、提取 Markdown、教学包、版本和发布信息。

## 默认知识检查

- `book-to-skill` 等知识处理阶段为每章生成默认知识检查题集，并让每道题关联
  对应知识点和学习目标。
- 题集随教学包一起审阅、发布和版本冻结；学生端直接加载已发布题集，不在答题
  时临时向模型索题。
- 首期题集仅采用可自动判定的题型。开放式简答与 PTC 解释性反馈属于后续能力。
- 学生答案、判定结果与题集版本构成学习证据；系统可据此提示复习，但不设强制
  通关或家长排期。

## 已确认的技术方向

- `book-to-skill` 继续负责教材内容的章节化与知识技能加工；
  `the-knowledge-guy` 继续负责基于这些材料的问答、引导学习与课程化能力。
- 教材加工是一条独立的 PTC pipeline。PDF 提取器应通过可替换适配层接入，当前
  可使用本地处理，未来可切换或补充 Datalab 等商业服务。
- 采用“对象存储保存可读资产 + 数据库存储关系、权限和发布状态”的混合模型，
  不采用 RAG 作为学生使用教材内容的主路径。

## 仍待讨论

- 家长编辑教材内容与教学包的首期交互范围，以及高级 Markdown 编辑何时开放；
- PTC 加工流程中的人工审阅点、失败恢复和重新生成体验；
- 一个学习空间能否挂载多个同等主教材，或采用一个主教材加多个参考材料；
- 知识检查的题型、自动判定边界、开放题的反馈方式；
- 学生对话、家长查看与批改的可见性边界；
- 打印、作业、打卡和教师协作等后续能力的优先级。
