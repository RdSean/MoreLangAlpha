# 家庭教材 PTC 教学加工设计

**状态：已批准。**

## 目标

将家庭教材的“内容提取”与“教学加工”分开。PDF 提取保持为可替换的确定性
处理阶段，当前使用本地提取器，未来可接入 Datalab。教学加工由受管 PTC 长程
任务运行 `book-to-skill` 与 `the-knowledge-guy`，为中国学生生成可审阅的教学
知识资产和默认知识检查。

本设计不把普通聊天线程当作教材加工界面，也不把 PTC sandbox 当作教材资产的
唯一存储位置。

## 边界与版本

每次内容提取产生不可变的内容版本，其中包含冻结的来源、章节 Markdown、页码
映射、提取器名称和版本。家长在内容版本完成后显式点击“生成教学包”。

教学加工任务冻结以下输入：

- 内容版本及其章节内容哈希；
- 教学目标和默认受众“中国学生”；
- `book-to-skill`、`the-knowledge-guy`、教材适配提示词的版本或内容哈希。

一个内容版本可对应多个教学包版本。重新生成或重试教学包不得重新提取 PDF；
将来 Datalab 生成新的内容版本时，也不改写已有教学包或发布版本。

发布版本冻结“内容版本 + 教学包版本”的组合。学生只能读取已经发布的组合。

## 受管 PTC 运行

教学加工创建一个由系统管理的 PTC workspace 和隐藏 thread。该 thread 只接受
服务端生成的固定任务说明，不能由家长作为普通聊天打开、追问或追加指令。

教育任务保存产品层状态、版本关系、授权与产物校验结果；PTC 任务账本保存每次
尝试的 `task_run`、checkpoint、SSE 事件、心跳、取消、worker 丢失和恢复链。

产品状态为：

```text
queued -> preparing -> building_skill -> generating_teaching -> validating
      -> review | failed | cancelled
```

产品状态必须由持久化 PTC 运行事件和服务端校验投影得出。前端不以本地计时器或
预估百分比伪造进度。

每次恢复创建新的 PTC run 并记录前驱关系。能从 checkpoint 续跑时使用原有恢复链；
如果 sandbox 已回收或 checkpoint 不可用，则由同一冻结输入创建新的受管 sandbox，
从最后一个已经验证的章节边界继续。已发布内容和其他教学包版本永不被失败尝试
覆盖。

## 数据与存储面

MinIO 是正式资产的唯一对象存储，所有教材资产继续使用 `education/` 前缀。受管
sandbox 不持有 MinIO 凭据、不读取 storage key，也不获得其他教材、家庭资料或
普通 Workspace 文件。

教育服务负责一次任务的受控数据搬运：

```text
教育服务读取已授权的冻结内容版本
  -> 上传 sandbox 的 /managed/textbook-job/<job>/inputs/
  -> PTC 只读取 inputs/ 并写入固定 outputs/
  -> 教育服务下载 outputs/
  -> 校验、落库、写入 education/ 下不可变教学包候选资产
```

`inputs/` 只包含章节 Markdown、最小 manifest 和任务契约；不会包含原始 storage
key、对象存储 URL、凭据或无关用户数据。`outputs/` 仅是短期候选产物。sandbox
回收不影响已冻结内容、已完成教学包或已发布版本。

## 双阶段 Skill 契约

教学任务按两个步骤运行：

1. `book-to-skill` 在受管 sandbox 内，根据冻结章节构建教材的知识技能中间表示。
2. `the-knowledge-guy` 仅基于该中间表示，以受限教材模式逐章生成面向中国学生的
   教学包和默认知识检查。

两项 Skill 当前的普通工作区文件与 HTML artifact 都是中间产物，不直接成为可发布
教材。教材适配层要求每章输出经过 schema 约束的 JSON/Markdown，至少包括：

- 学习目标、核心知识点、重点难点和必要前置知识；
- 面向中国学生的中文解释与学习建议；
- 与知识点关联、可自动判定的默认题集；
- 章节来源、输入内容哈希和各 Skill/提示词版本。

服务端在回收输出时检查章节覆盖、输入哈希、字段大小、题目选项与正确答案、知识
点关联和重复项。只有全部验证通过的产物才被写入 PostgreSQL 与 `education/` 下的
候选教学包。Agent 不能直接发布，也不能将自己的过程文件提升为正式资产。

## 家长界面

教材详情页中的“教学加工”面板是唯一的主界面，不新增传统 PTC chat 页面。

面板显示：

- 当前阶段、已完成章节数、最近心跳、运行耗时和下一步操作；
- 状态允许时的取消、继续运行和重新生成；
- 完成后的教学包审阅、发布和分配入口。

“查看运行”在同页以抽屉或二级标签展示。它复用同一 PTC run ledger 与 SSE 数据，
展示脱敏的阶段时间线、逐章进度、尝试链、工具动作摘要和可操作的失败原因。它不
复制聊天界面，也不允许家长中途修改 Agent 指令。所有路径、凭据、对象键、原始
对象存储地址和不属于本任务的输入都必须在服务端过滤。

## 权限与失败处理

只有同一家庭的家长可以创建、查看、取消或恢复教材教学任务。学生不能读取任务、
中间产物、运行详情或未发布教学包。家长只可查看自己家庭教材的脱敏运行投影。

取消必须写入持久化取消意图，再通知 PTC 运行。worker 丢失、sandbox 不可用、Skill
输出不合格和服务端存储失败都记录为可区分的失败原因。重新生成保留失败尝试和
运行链，不能静默覆盖审阅中或已发布教学包。

## 验收原则

- 真实家长可在当前 worktree 的真实 `5177` / `8000` 服务中，从已提取内容创建、
  观察并完成一条教学加工任务；
- 页面显示真实 PTC 事件投影和恢复链，而非 mock 或本地轮询假进度；
- 产物通过服务端校验后才出现在家长审阅中，且 API 不泄露 storage key 或 MinIO URL；
- 已发布教材、其他家庭教材及无关 MinIO 对象保持不变；
- 单元测试、mock E2E、构建/lint 与真实服务验收分别报告。
