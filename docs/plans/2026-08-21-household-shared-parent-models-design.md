# 家庭共享家长模型配置设计

**状态：已批准（2026-08-21）。**

## 背景与目标

当前实现同时维护家长用户级模型配置和独立的家庭模型池。两套配置重复保存供应商、模型、Base URL 和凭证，既没有同步关系，也没有多家长合并规则，因此会出现家长已配置模型但学生模型池为空、学生界面显示模型但运行时不可用等不一致。

本次改造将家长在 `/settings?tab=model`（以及现有 Setup/Provider 配置入口）维护的模型作为家庭唯一共享来源。学生可以使用该来源中全部实际可调用的模型并保存个人选择，但不能维护供应商、Endpoint 或凭证。

当前数据库为测试数据，允许清理旧家庭模型池记录、相关偏好和测试对话，不设计历史双轨兼容迁移。

## 方案决策

### 家长用户级配置是唯一来源

家庭不再拥有第二份 Endpoint/密钥存储。运行时通过家庭成员关系找到家庭的模型管理员，再读取模型管理员现有的 `user_api_keys`、模型偏好和自定义模型配置，实时生成学生可用模型投影。

家庭创建者是唯一模型管理员和凭据归属人。创建家庭时将其用户 ID 保存为 `model_owner_user_id`；其他 parent 可以使用家庭模型，但不能写入或合并自己的模型配置。这样可明确账单、撤销和配置来源，避免多个家长的同名模型或密钥冲突。

### 学生只保存模型引用

保留轻量的 `student_llm_preferences`（或等价字段），只记录学生选择的稳定模型引用、家庭归属和更新时间。该表不保存 API Key、Base URL 或供应商凭证。模型管理员删除或禁用模型后，学生偏好在读取时失效并回退到管理员默认模型；没有可用模型时返回空状态。

## 数据与运行时流程

```text
家庭创建者 user_api_keys + user_preferences/custom_models
                         |
                         v
             家庭成员可用模型只读投影
                         |
              +----------+----------+
              |                     |
       学生当前模型偏好        LLM 运行时解析
       （只存引用）             （使用管理员凭据）
```

“全部模型”指模型管理员当前具备有效凭据、且平台目录或自定义配置声明可调用的模型，不等于无凭据的全局目录条目。模型投影应返回稳定的公开模型键、显示名称、供应商和可选能力摘要，不返回密钥或敏感 Base URL。

学生解析顺序为：有效的个人偏好 -> 模型管理员设置的默认模型 -> 无模型。首次进入没有个人偏好时使用管理员默认值；学生主动切换后只影响自己。管理员新增、修改、禁用或删除模型后，学生下一次查询和请求实时反映最新结果。

家长自己的运行路径继续使用其个人配置；如家长在家庭模型页面之外切换个人默认模型，该配置同时决定学生首次加载时的默认模型，但不会覆盖学生已经保存的偏好。

## 接口与界面

### 家长

- `/settings?tab=model` 保留为唯一的模型和供应商管理入口。
- 删除独立的家庭模型池设置页、家庭 Endpoint CRUD 弹窗及其导航入口。
- 家长可继续新增、编辑、删除供应商凭证和自定义模型；这些变更自动成为家庭成员下一次请求的可用模型来源。
- 后端仅允许 `model_owner_user_id` 修改共享模型配置；其他 parent 的普通个人模型配置不进入家庭投影。

### 学生

- 学生设置页不显示 Provider、API Key、Base URL、Primary/Flash 管理或 Connected Accounts 等个人配置控件。
- 聊天模型选择器显示家庭共享源的全部实际可用模型，允许切换并保存自己的偏好。
- 可在设置页只读查看当前家庭可用模型和当前偏好，但不提供管理操作。
- 家庭没有有效模型时显示“家庭尚未配置可用模型”，不展示 Sonnet5 等占位或个人模型目录，也不进入发送请求流程。

建议将 `/api/v1/family/llm-availability` 改为从模型管理员配置实时计算；`/api/v1/family/llm-preference` 仅接受学生自己的公开模型键。旧的 `/api/v1/family/llm-pool` 管理接口及其数据库访问层应移除或返回明确的弃用结果，避免继续产生第二个来源。

## 权限、安全与历史记录

- 所有家庭归属、管理员身份和模型键有效性都在后端校验，不能信任前端传入的 household 或 owner ID。
- 学生永远不能读取管理员 API Key、解密凭证、完整 Base URL 或其他敏感连接信息。
- LLM 运行时使用管理员凭据，但审计记录保留家庭 ID、学生发起者、公开模型键和最终模型名称快照。
- 模型后续改名、禁用或删除不改变已经完成的会话历史；历史记录使用运行时保存的非敏感快照。
- 移除家庭成员关系后，模型投影、偏好更新和运行时解析立即失效。

## 错误处理

- 没有模型管理员、管理员没有有效凭据或模型投影为空：返回可区分的无模型状态，不创建 run。
- 学生请求不存在、已禁用或不属于家庭的模型键：返回无模型/不可用错误，不回退到个人凭据。
- 非管理员 parent 尝试修改共享模型：返回 `403`；学生访问管理接口同样返回 `403`。
- 管理员配置变更与学生请求并发时，以请求解析时的数据库状态为准；已经开始的运行不被中途切断。

## 验证范围

后端测试覆盖：管理员身份与家庭归属、全部模型投影、默认与学生偏好优先级、偏好失效回退、无模型状态、跨家庭访问、学生禁止个人凭据、凭证不出现在响应和日志中，以及账单/历史模型快照。

前端测试覆盖：家长只通过既有模型页管理配置、学生模型选择器显示全部可用模型并持久化选择、管理员新增或禁用后学生刷新即可看到变化、空状态文案和学生侧无管理入口。

验收标准是：家长只配置一次模型；学生无需单独配置即可看到并使用全部实际可用模型；学生可独立保存选择；任何没有有效模型的状态都明确可诊断，不再显示与运行时不一致的占位模型。
