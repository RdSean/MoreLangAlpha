## 1. 现状与设计选择

`create_textbook_from_library_source()` 先 `freeze_book_source()`，再创建教材和结构任务。冻结包含逐资源读取、写入教材私有对象、读回校验、manifest 写入与主文件规范化。本次 SB3 冻结约 159 秒，发生在任务受理之前；浏览器因此既没有教材 ID，也没有任务可订阅。worker 随后的 `stage_book_execution()` 才把冻结产物复制到 Docker。这是两个不同区间，不合并称为“图片导入”。

现有能力可以复用：PG 任务队列、逐 item attempt/lease/token、恢复巡检、业务活动预算、Redis 唤醒提示、SSE 回放、React Query 快照、名句小池。当前 `book_phase()` 主要写日志，job/item 只有开始结束时间，尚不能给前端稳定提供全过程分段统计。

方案比较：

| 方案 | 能解决的问题 | 代价/限制 |
| --- | --- | --- |
| 推荐：现有结构 item 增加模型前准备阶段 | 快速受理、恢复、实时计数、同一任务时间线 | 要明确未冻结来源状态与无 PTC run 的恢复分支 |
| 仅在等待弹窗加入文案/计时 | 改动较小 | 请求仍阻塞，关闭页面与服务退出后难恢复，无真实资源进度 |
| 引入 Redis/Celery 类独立准备队列 | 可另行调度准备任务 | 与现有 PG 队列、租约和取消机制重复，增加跨队列一致性成本 |

采用第一种。来源准备不是新的知识点，也不是一次模型执行，不增加 item kind 或独立处理页；结构任务仍只有一份结构交付物。不得把准备完成算成结构成功或额外一份讲义。

## 2. 快速受理与来源状态

### 2.1 请求链路

POST 只做权限、参数、来源所属关系、解析已完成、主产物匹配、路径和资源元数据校验，并固定该解析 bundle 的元数据清单。禁止在请求里读取完整对象、复制图片或连接 Docker。

短事务登记“已绑定固定来源、尚未准备就绪”的教材、初始结构 job/item 和持久准备清单。返回 `202 Accepted`，包含原有 textbook_id/job_id，并明确新受理还是复用已有教材。前端立即关闭来源选择框并进入工作台处理视图。API 快响应目标是在慢存储注入下仍约 2 秒内返回；这是受控验收目标，不承诺任意数据库/网络条件下的 SLA。

同家庭/同解析产物仍唯一。相同幂等键的不同请求拒绝；两次并发添加同来源只创建一套教材与任务。复用已完成教材时进入阅读，不伪造一轮新的处理。响应丢失可用原幂等键再次确认，不能重新复制一整套产物。

提前登记不意味着允许创建无来源空教材：固定 document/parse/primary 身份，准备失败也不切换到最新解析。原设计中“冻结成功后才创建记录”的内部顺序在本增量中被替代，固定单源与完整校验后才调用模型的边界不变。

### 2.2 数据与可读性

教材增加 `source_status`：pending/preparing/ready/failed/cancelled，以及真实 `source_frozen_at`。固定来源身份和解析元数据始终非空；尚未校验的冻结 Markdown digest、size、snapshot prefix/key 不写假值，允许未就绪时为空，通过约束保证 ready 时完整且路径归属正确。

工作台的 `source` 只在 ready 时返回 FrozenBookSource；另外返回安全的 selected_source 元数据和 source_status。`frozen_at` 不再使用教材 created_at 冒充。结构状态仍按任务/结构记录推导，增加 source 状态只解决准备可见性，不制造第二份任务状态真值。

公共契约：受理字段 `acceptance` 为 `accepted_new` 或 `reused`；selected_source 中的摘要/大小仅为固定解析元数据，只有 source 中的摘要才代表已验证冻结内容。准备快照 `total_resources` 未知时为 null，`verified_resources` 独立于 job 交付计数。当前 attempt 的 timing_summary 与统计历史均以 null 表示无证据耗时，七类 phase 之外的 Agent 动作不生成计时区间。旧客户端/快照兼容字段默认 ready，但新 pending 必须明确给出 source_status 与 selected_source。

准备中不能读尚未提交的部分来源、建半成品树、生成讲义或分配学生。来源 ready、结构仍分析时，如有已有原文入口可继续读取固定来源；结构失败后保留已冻结原文。旧教材迁移为 ready，旧冻结时间没有证据则未知，不从 created_at 补造。

## 3. 后台执行、恢复和存储保护

### 3.1 单个结构 attempt 的执行链

~~~text
受理/等待
  -> 准备固定来源（无模型、无 sandbox）
  -> 来源校验并提交 ready
  -> 等待 PTC 运行资源
  -> sandbox 准备 -> 输入 staging -> PTC 执行
  -> 验收与提交 -> 结构可读
~~~

准备沿用该 structure item 的 attempt_token、execution_id 与租约；增加服务所有的 execution_phase，不拿 Agent 的 stage/action 充当状态机。来源已 ready 的结构重试跳过冻结。material/supplementary 从等待 PTC 开始，继续复用已冻结来源。

长准备不能阻塞 `scan_once()` 的恢复/取消/清理巡检，也不能长时间占用数据库事务或 PTC graph 容量。准备使用有界本地执行任务，PG 是跨 worker 状态真值；准备并发由 PG 原子门控，默认全部署 1 份，单教材资源先顺序复制。只在来源 ready 后申请既有 PTC 容量；等待资源时租约和取消仍可观察。不得仅靠单进程 Semaphore 宣称跨 worker 上限。

### 3.2 对象、准备进度与完成提交

每 attempt 写入独立 `education/<household>/textbooks/<book>/source/attempts/<attempt-token>/` 子前缀，manifest/相对路径布局沿用现有读取契约。全部写入并读回 SHA 校验、manifest 校验、主文件规范化成功后，以当前 token、来源身份、未取消和父对象仍存在为条件，原子提交来源指针与 ready 状态。之后来源不可变。

新 prefix 约束允许精确的 attempt 子前缀；旧 ready 前缀继续可读，不为本改进删除旧教材或重新冻结。对象布局变化必须同时覆盖 source reader、image URL、staging、恢复、候选清理和删除保护，而非只改上传端。

只在写入及读回校验都成功后递增 `verified_resources`。分母是固定清单内需要复制的全部解析资源，不把它误称为图片数；manifest sealing 不占其中一个“图片”。总字节未知时不展示字节百分比；未知分母不展示 0/0 或估算完成率。到 N/N 后仍可显示“校验来源清单”，不提前宣告就绪。

每次外部写入前持久记录本 attempt 的候选键，复用既有删除/上传协调保护；不能只靠进程内 written_keys 处理断电。清理显式排除已提交 ready 来源引用，尤其结构后来失败时不得误删成功准备的原文。迟到旧 worker 最多写自己隔离的候选对象，不能覆盖新 attempt、提升 ready 或删除别人的对象。

### 3.3 取消、失败和恢复

- no-run 的准备/等待资源阶段不能被现有 recovery 当作“PTC run 丢失”直接失败；按 execution_phase 和 lease 恢复。
- 租约到期后，新 worker 先原子夺取恢复权并 fence 旧 token，再将无 run 的中断 attempt 收尾，创建新 attempt 重新准备；已提交 ready 来源保留并复用。不同时续用旧 token 写同一前缀。
- 首版不承诺跨 attempt 的逐文件断点复用；准备重启明确显示“重新准备”，计数重新开始。若来源已提交 ready，重试仅处理未完成的结构执行。
- source 写入失败、资源缺失或 digest 不匹配使任务明确失败，保持绑定与重试入口；未准备完整绝不启动模型。没有被动修改来源/无限自动重试。
- 取消持久 fence 优先；进行中的存储操作允许有限时间收尾，但禁止后续 ready/模型提交。不能把取消即时当作所有线程 IO 已停止。
- 活跃/未收尾上传依然阻止永久删除；终态后的异步候选清理可重试。教材删除保留图书馆原件/解析 bundle，与现有家长权限一致。
- Redis 通知、SSE 或 LangSmith 不可用不改变队列真值。PG 关键准备 checkpoint/完成事务失败时不能假装成功；非关键计时上传失败则标记计时缺失，不阻止已经成立的业务提交。

## 4. 统计计时契约

### 4.1 三类信息严格分开

| 信息 | 来源 | 前端措辞 |
| --- | --- | --- |
| 服务端受理/准备/执行/提交边界 | 数据库状态、执行边界与 monotonic | 总用时、来源准备、等待运行、输入准备、PTC 执行、验收提交 |
| Agent 业务动作 | 既有受限 report_progress | 动作名称与上报时间，不标精确阶段耗时 |
| 工具活动/租约健康 | 诊断事件或独立 worker 状态 | 最近活动/worker 状态，不冒充某一步完成 |

“PTC 执行”包含模型响应、工具和运行衔接，不叫“纯模型思考耗时”。精确 LLM 次数、TTFT、tokens 不属于首版 UI；LangSmith 缺失问题另列改进，不让前端统计依赖外部 trace 完整性，也不重复建一套通用 PTC 计费层。

job 增加 request_round/round_accepted_at：首次受理为第 1 轮，用户手动重试在同一事务递增轮次并重设起点；准备崩溃后的自动恢复只增加 attempt，不新开用户请求轮次。持久 `education_book_job_attempts` 保留每次 attempt 所属轮次、排队起点、claim/start、状态、token/execution/run 关联及安全计时状态；`education_book_job_phase_spans` 保存固定阶段的每段测量窗口（唯一 segment_id，开始/结束/状态/同进程 measured_duration_ms）。恢复提交另起一段，不跨进程续用 monotonic 或重复累计同一段。

job/item 快照只带当前 attempt 的紧凑汇总。历史 attempt/批量统计详情按 item 游标分页，不在每次 SSE/5 秒快照里重复传全部时间窗口、正文或来源清单。状态/产物成功仍取现有 job/item，不由计时状态决定。

### 4.2 口径和显示

- 本次请求总用时：本轮 round_accepted_at 到本轮终态，包含来源准备、等待和中断恢复；各 attempt 另有自身 queued_at/终态区间。用户 retry 创建新的轮次/queued_at，不能用首次 job.created_at 把用户隔夜等待算成新一轮加工。
- 来源准备：worker 真正开始冻结至 ready；初始等待不算进来源复制。
- 等待运行：PTC 容量等待，与来源准备前等待分开记录；批量中后续 item 等待前项的时间也标明为等待，不全部归给模型。
- 输入准备：sandbox_preparation 与 input_staging；统计明细可分开展示，两者属于同一个父区间，禁止父子重复相加。
- PTC 执行：教育 workflow 实际执行边界至 terminal callback 开始前，不把 graph 装配时刻当作真正执行开始。
- 验收提交：模型执行结束后校验、对象归档和数据库业务提交；恢复等待独立说明，不伪造连续单次提交。
- 状态终态后计时停止；失败/取消同样记录耗时和终止区间。source ready 或模型完成不等于任务完成，验收后成功才打完成勾。
- 批量：批次本轮总墙钟与每知识点 attempt 用时分别展示；摘要的中位/最长时间仅取本轮成功 material attempt，并显示样本数，附加材料单列。N/M 仍按该 job 已可靠提交的全部 material（包括上轮成功保留项），与本轮耗时样本数明确区分。求和不冒充批次墙钟，失败不从历史中消失。
- 历史计时未知用“未记录”，无证据区间不填 0；partial 统计不以相减补齐明细。服务时钟倒退/负区间标记不可用，不显示负数。

返回 server_now、状态更新时间/有效截止点和 phase started_at。前端用服务器基准加本地 monotonic 更新活跃时钟，每页共享一个 1 秒 tick；每秒不发请求。后台页停止动画/tick，回来重新取快照并校时；断线显示“连接中断，计时截至最后确认”，不无限累计并暗示 worker 一直工作。

## 5. 全屏处理视图

### 5.1 路由与进入退出

仍只有 `/textbooks` 与 `/textbooks/:id` 两层。增加 `?activity=<job-id>&panel=processing` 作为同一工作台的整页处理视图，不恢复旧 processing/structure/candidates/审核页面，也不使用浏览器 Fullscreen API。

新教材受理后默认整页时间线。家长提交单讲义/批量任务后进入该视图，保留 kp/node/view；可随时点击“返回阅读”回到同一工作台，任务继续。现有紧凑活动面板和“展开处理”图标保留，二者共用活动投影与订阅，不能各起一条 SSE。已有 ready 教材从列表正常进入阅读，不因后台有生成就强制全屏。

刷新/跨标签/历史返回通过 URL +快照恢复。任务属于另一教材、job 已不存在或学生访问时明确拒绝/回到合法视图，不泄露任务信息。完成后保留结果与计时，提供“进入阅读/阅读讲义”；没有 1 秒强制跳转。首份批量讲义提交后即可阅读，不等全批次完成。

讲义视图标题显示当前知识点；批量按知识点分组，显示每份可靠终态与用时，未完成/失败/旧版仍可读明确区分。完成节点可打开讲义；大批次折叠已完成组、按页加载历史，活动预算和客户端缓存上限不因全屏而取消。

### 5.3 长等待、名句与诊断

保留已实现的工具活动作为“最近活动”证据，工具名/参数只在家长诊断明细。存储准备同样可更新最近活动，但租约续期不触发名句、不伪造资源增长。

名句沿用按需小池与 5 秒冷却：只由新鲜活动触发；回放、重复 seq、断线、后台标签或终态不换句，不排队，不重载根 mingju.json。只有新的后台复制确认/工具活动才作为本轮鲜活证据；沉默不等于失败，不凭长时间无工具事件判断模型已停止。

用户向上查看历史时不强制下滚；跟随最新由显式按钮恢复。计时与名句区域尺寸稳定，标题换行，诊断展开不遮住取消/阅读入口。

### 5.4 视觉和可访问性

按 DESIGN.md 的 Quiet Workspace、现有主题 token、字体、Lucide 图标和共享 Loader 实现；全宽页面内约 760–960px 可读内容，无套卡片或装饰背景。整页主要一个纵向滚动区，移动端 375px 保持完整操作，长标题和数字不横溢。

色彩不是唯一状态提示；图标按钮有 Tooltip/可访问名称，关键点击区约 44px；键盘焦点、错误提示、屏幕阅读器状态播报与 reduced-motion 纳入验收。计时秒跳和名句不反复 aria-live 播报，暗色/亮色都检查。

## 6. 活动、快照与边界

准备资源计数在 attempt 快照持久更新；SSE 每至多 1 秒合并一条资源进度，同期即使已超活动明细预算，快照仍能读到最新准确计数。ready/失败/取消等事实通过事务状态恢复，不靠明细事件存在才展示。

不改变现有 1000 条/1 MiB 总预算、工具子预算、2 KiB 单事件限制、独立消费游标、终态回放与 activity_status=unavailable 语义。新活动 metadata 只含服务白名单计数/阶段/attempt，不含存储键、模型私有推理、正文或凭据。

活跃前台 job 快照沿用最多每 5 秒兜底读取、终态最终刷新、后台恢复重新同步。最后工具活动、资源确认和 worker lease 健康各自有字段/标识，不共用一个“活动时间”制造假心跳。统计表写入权限与 job 属同一家庭，仅家长可访问。

## 7. 验收与非目标

必须覆盖快速受理、慢存储真实计数、来源复制中断/响应丢失/提交 ACK 丢失、无 run 跨进程恢复、租约竞争、取消及迟到写入、已冻结来源在结构失败后保留、pending 删除与图书馆原件保护。

前端覆盖结构/单讲义/批量/附加材料、成功/部分失败/取消/重试、刷新/回放/预算耗尽/活动 unavailable、断线校时、历史未知计时、主题/375px/键盘/长标题。实测未来取得用户授权后使用专用或用户指定数据，不删除现有教材制造验收条件。

本增量不解决 SB3 的语义切分/标题质量，不修改 more-to-skills 动作集合或提示，不提高推理强度、不做多模型对照、不修复 LangSmith SDK 上传、不重写 PTC/MCP/checkpoint。任何不可测区间明确未知，完成 UI 不宣称教材内容质量全部通过。
