# 自然语言布置作业工具设计

## 目标

让家长在任意 PTC 或 Flash 聊天窗口中，通过自然语言创建文字版家庭作业。第一阶段只处理学生、学科、作业类型、练习来源、截止时间、重复规则和文字说明，不接入图片或 PDF 附件。

## 方案

采用“内置平台工具 + 默认 Skill”组合，而不是单独部署外部 MCP Server。

- 内置工具负责结构化参数、家庭权限、字典校验、家庭时区、重复规则和幂等写入。
- 默认 Skill 负责识别“布置作业”意图、把中文表达映射到工具字段，并在关键字段缺失或有歧义时追问。
- PTC 与 Flash 都注册同一个内置工具，因此家长不受窗口类型限制。
- 工具最终调用现有 `src/server/services/education_tasks.py:create_task()`，网页接口和自然语言入口共享同一套业务规则。

## 工具契约

工具暂定名称为 `education_create_homework`。输入包含：

- `student_name` 或已解析的学生标识
- `subject_code`
- `type_code`
- `practice_source_code`（仅练习类型）
- 家庭时区下的 `due_at`
- `frequency` 与可选 `weekdays`
- `description`

工具不接受调用方提供的 `parent_user_id` 或 `household_id`，这些值从当前认证上下文解析。服务端继续要求家长、同家庭学生、学生年级、学科映射和练习来源合法。工具生成幂等键，普通网络重试不得重复创建作业规则或任务实例。

## 对话行为

信息完整且唯一时直接创建，例如“给墨墨布置数学练习，明天晚上八点完成”。缺少或存在歧义时只追问必要字段，例如家庭中有多个学生时询问目标学生。模型不得仅用文字声称创建成功，必须得到工具成功结果后再反馈任务摘要和返回作业列表的链接。

不强制每次弹出额外确认框；明确的家长指令视为创建意图。工具错误以可读的字段或权限错误返回，Skill 只负责解释，不绕过服务端校验。

## 权限边界

工具可在 PTC/Flash 工具列表中注册，但服务层只允许家长调用。学生即使构造工具参数也会被拒绝。该工具不作为用户可配置的 workspace MCP 暴露，避免学生继承、沙箱包装或 Vault 配置造成权限旁路。

## 非目标

- 第一阶段不处理聊天附件、图片、PDF 或 MinIO 资产关联。
- 不新增独立作业数据库模型、队列或后台任务。
- 不复制网页端作业业务逻辑。

## 后续附件扩展

文字版本稳定后，再为工具增加当前聊天附件到 `education_assets` 的映射，并复用现有的附件归属、暂存、清理和下载规则。该扩展不改变本阶段工具的权限和任务创建服务。
