# K12 家庭作业工作流设计

## 目标

家庭作业模块用于支持家长向家庭学生布置学习任务，学生查看每日和未来任务、完成打卡并可选提交作业照片或 PDF，家长随后可以查看、反馈和要求补充。任务是否完成与后续批改完全分离。

本阶段保留家庭教育模块与通用 Agent 运行时的边界，不把作业附件、学生提交或家长反馈暴露给 PTC、沙箱或其它家庭成员。

## 数据模型

### 学生档案

新增学生档案，保存学生当前年级 `grade_code`。家长在家庭账户管理中设置或修改年级。创建作业时自动读取当前年级；作业规则和已物化任务保存年级快照，学生升年级不会改写历史任务。

### 作业规则和任务实例

`education_task_rules` 保存家长创建的规则，增加以下分类字段：

- `subject_code`
- `type_code`
- `practice_source_code`，仅作业类型为 `practice` 时允许填写
- `grade_code`
- 重复规则

`education_tasks` 保存规则生成的具体日期实例，并保存同样的分类快照。任务完成记录独立保存 `completed_at`。

重复规则首版支持：

- 一次
- 每天
- 工作日
- 每周指定星期

不引入 Cron 或任意间隔表达式。规则停止后，已经生成的任务、打卡、提交和反馈全部保留。

### 完成、提交和反馈

任务状态收敛为：

- `open`
- `completed`
- `cancelled`

学生首次点击“完成打卡”时立即写入 `completed_at` 并将状态改为 `completed`。打卡可以没有文字和附件。

学生的每次打卡、补充或修改都是不可变的提交记录，可带文字和多份附件。首次打卡和后续提交不改变已完成事实。

家长反馈改为可追加记录，可表达普通反馈或“建议修改”。反馈不会把任务恢复为未完成，也不覆盖之前的提交和反馈。

### 附件

复用 `education_assets` 表和现有私有对象存储，所有对象使用 `education/` 前缀。家长原件和学生提交附件分别关联到任务或提交记录。

每次提交允许多份图片或 PDF。附件元数据可以返回给授权家庭成员；下载和预览使用短期签名 URL，永不返回内部对象 key。任务详情分为“家长布置的原件”和“学生提交的附件”两段。

## API 和权限

家长可以：

- 创建任务、停止重复规则、取消未完成任务
- 查看家庭学生任务
- 查看家长原件、学生提交和全部反馈
- 追加反馈或建议修改

学生可以：

- 查看分配给自己的任务
- 首次打卡并可选上传多份附件
- 对已完成任务追加提交
- 查看家长原件、自己的提交和家长反馈

服务端每次操作都通过家庭成员关系和任务分配人校验。学生不能创建、取消、修改任务规则，也不能查看其它学生的任务或附件。家长只能访问同家庭学生数据。

## 家长端交互

作业页包含学生切换器、月度学科热力日历、完成汇总和创建入口。创建表单依次选择学生、学科、作业类型、练习来源（仅练习显示）、标题、说明、截止时间、重复方式及多份家长原件。

任务详情显示任务分类与截止信息，然后依次显示：

1. 家长布置的原件
2. 学生首次打卡和提交历史
3. 反馈记录

已完成任务可以继续查看和追加反馈；取消仅对未完成任务开放。

## 学生端交互

学生作业页显示自己的月度热力日历、今日待完成、即将到期、逾期和已完成列表。进入任务详情后，家长原件位于上半段，学生提交历史位于下半段。

“完成打卡”按钮立即完成任务，不要求文字或附件。附件上传是可选动作，可在首次打卡时或之后通过“补充提交”完成。家长要求修改只显示提示，不影响任务已完成状态。

## 热力日历

日历颜色只代表学科，完成状态使用勾选、空心或逾期提示表达。同一天存在多个学科时保留多条颜色任务条。点击日期后展示该日完整任务列表；日历格不直接承载长标题或附件。

家长可以切换子女查看，学生只能查看自己的日历。统计至少包括今日待完成、本周完成和逾期数量。

## 错误和一致性

- 首次打卡、提交附件和任务状态更新在同一事务内完成；失败时不留下半条提交记录。
- 对提交使用幂等键，网络重试不会重复产生同一提交。
- 对象上传成功而数据库写入失败时执行补偿删除；数据库记录存在但签名 URL 生成失败时返回存储不可用，不泄露对象信息。
- 任务详情只返回授权范围内的数据；跨家庭、未分配学生或不存在的资产统一返回安全的未找到或无权限响应。

## 实施阶段

1. 新增学生档案、任务分类字段和重复规则迁移，改造完成与提交数据库模型。
2. 实现任务详情、打卡、追加提交、多附件和反馈 API，并补充权限与事务测试。
3. 改造家长和学生任务列表、详情、附件展示及创建表单。
4. 增加月度学科热力日历、完成统计和筛选交互。
