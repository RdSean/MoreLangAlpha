# more-to-skills 教材处理重构设计

日期：2026-09-30。版本：第二轮架构与交互审查修订。
状态：设计阶段；本轮没有实施业务代码、数据库迁移、数据删除或服务重启。
配套文档：[实施计划](2026-09-30-more-to-skills-implementation.md)、[清理范围与验收清单](2026-09-30-more-to-skills-cleanup-audit.md)。

## 1. 第二轮结论与已确认边界

第一版方向正确，但不足以直接开工：旧页面仍作为改造对象，精确删表范围被推迟到实施阶段，图书馆反向查询与学生功能依赖漏列，批量产物提交及崩溃恢复没有明确边界。本版替换这些模糊决策，不再围绕旧四阶段加工流程扩展。

用户已确认：
- 严格遵从新版 more-to-skills 的 SKILL.md、SPEC.md、schema 和现有颗粒度，不另设教学质量评分或细分目标。
- Structure Only 包含 nodes 和 knowledge_points；Reading Material Only 允许从任意 KP 开始，按技能规则补齐邻近上下文。
- 讲义直接采用 chapters/<kp.id>-<slug>.md；清理旧讲义任务，不再做第二轮课程转译。
- 旧教材历史数据和偏好不用迁移；用户手动拆分/合并/候选审阅不再提供。
- 输入来自图书馆已处理好的 Markdown 与图片，不重复解析和 OCR。
- 保留 PTC 自编、修改、执行脚本的能力，简化配置，保留正常运行机制和学生权限边界。
- Timeline 使用有界精简事件，不能恢复全量 SSE 入 Redis。

本版的进一步设计决策：
- 家长仅有“教材列表 → 教材工作台”两层；独立版本、处理、结构审阅、候选确认、课程审核页面删除。
- 一本教材绑定一个固定图书馆解析产物，不创建空教材再逐层添加版本/来源；首次分析成功后不提供结构编辑或重分割入口。更换解析产物新建教材，不悄悄迁移学习内容。
- 学生分配仍是家长的明确操作，但取消逐讲义审核和独立发布版本。已分配学生读取该教材最新成功讲义，生成中/失败的新结果不替换当前可读内容。该行为取代旧的不可变 publication 快照。
- 学生阅读、学习进度、笔记、总结和 Flash 追问能力保留并改接新引用，旧记录可清空；不因删除旧表而意外删除功能。

## 2. 现场证据

2026-09-30 只读查看用户指定的处理页、候选页，并沿可见入口检查教材详情和单知识点课程页：
- 处理页宣称“四阶段全部完成”，实际详情仍显示“知识点 24/24 已接受，课程 2/24 已通过”；处理完成与课程可读混为一谈。
- 候选页展开所有结构节点及摘要，包括大量“0 个候选”卡片，形成很长的嵌套页面。
- 候选页进入课程后，“返回”指向结构审阅，不是进入时的候选页；课程页又有发布按钮和 revision 历史。
- 来源选择支持多份 Markdown 合并，和新 schema 的单源坐标系冲突。
- 旧版本/发布表被图书馆 teaching-usage、学生笔记/进度/总结、学习 Flash 上下文继续引用。
- PTC 核心中有 textbook-chapter-worker 的 fixed v2 asset 提示词；executor 仍识别多种旧 education managed kind。
- education_generation_jobs/attempts/events 是旧教育业务表，不是必须原样保留的通用运行账本。

## 3. 信息架构与工作台

家长路由：
- /textbooks：教材列表，点击一行直接进入工作台。
- /textbooks/<book-id>：唯一教材工作台。
- 查询参数表达选择：?kp=<skill-kp-id>&view=material 或 ?node=<node-id>&view=source。
- ?activity=<job-id> 只打开工作台内的活动面板，不形成下一层页面。

旧 /versions/.../processing、structure、candidates、knowledge/... 路由及页面组件移除；提供一条路由级“旧教材已重置，返回教材列表”说明，不加载旧 schema、不保留旧页运行逻辑。查询目标不存在时在工作台提示并回到有效默认选择，不能静默读到另一本书。

~~~text
教材列表 / Reading Explorer 2       结构已就绪 · 讲义 7/112      活动  给学生使用  更多
┌───────────────────────┬────────────────────────────────────────┐
│ 知识点 | 原书目录      │ Sweet Love 2                    生成讲义 │
│ 搜索标题              │ 讲义 | 原文                              │
│ Unit 1                │                                        │
│   Sweet Love 1   已生成│ 讲义正文 / 定位后的原文                  │
│   Sweet Love 2   未生成│                                        │
│   Reading Skill 未生成│                                        │
│ Unit 2 …              │                                        │
│ [批量选择]            │                                        │
└───────────────────────┴────────────────────────────────────────┘

~~~

活动面板按需从右侧展开或占用底部区域，不常驻第三列。全局侧栏沿用现有折叠方式，不再叠加另一套全屏流程导航。窄屏采用目录抽屉和一个正文区；活动与生成表单不叠加多层弹窗。

原书目录按 nodes.children 递归显示；知识点视图按 unit 分组，保留 schema 顺序和 nodes 多引用，不把 KP 硬塞入目录的某一层。前置/附录等无 KP 节点在原书目录可读，不在知识点视图展开成“零候选”卡片。无 unit 的 KP 放“未分组”，不生成假的节点。

## 4. 完整交互链路

### 4.1 从图书馆开始

图书馆已完成解析结果提供“用作教材”；教材列表的“从图书馆添加”打开同一个单选来源面板。条目显示文件名和解析时间，存在多个解析结果时默认最新成功结果并可切换，不能把不同结果混用。

选定后名称默认来自文档，可直接修改。主按钮“添加并分析”一次完成来源绑定、创建教材和结构任务，然后进入工作台。重复点击由请求幂等键去重；同一家庭与相同解析产物已有教材时优先打开已有教材，避免误建重复记录。不在创建成功后再要求用户点击第二次“开始处理”。

默认只分析结构；在展开选项中可指定随后生成全部讲义或全部文件。它们只是持久保存的后续处理意图，不增加一套 Agent 配置，也不要求用户守着页面手动接下一步。

没有可用解析产物时明确引导去图书馆解析，不重新提供教材上传/OCR入口。固定源快照成功后再执行模型；源文件或必要图片缺失是来源准备错误，有具体失败信息。

### 4.2 结构分析与首次完成

分析中，工作台展示任务状态、耗时、精简活动，可查看固定原文；导航区说明“结构分析中”，不把半成品树冒充可用结果。可离开页面，任务继续。

服务端校验和事务导入成功后，同一页面出现目录和知识点；状态是“结构已就绪，讲义 0/N”，不写“全部加工完成”。优先打开首个 KP 的原文，若用户正阅读别处则不抢选择和滚动位置。

结构失败时保留原文及错误，提供“重试分析”，不展示一套全部勾选的阶段卡。knowledge_points=[] 的有效结果仍可浏览 nodes，明确“未提取到知识点”，生成讲义入口不可用；不为满足计数编造知识点。

### 4.3 单条讲义

点击 KP 只更新工作台选择和 URL：
- 有成功讲义：默认显示讲义；可以切原文。
- 没有讲义：默认显示原文，并有“生成讲义”按钮。
- 点击目录节点：显示其原文范围及关联 KP，不触发生成。
- 生成表单在当前正文区展开，只含深度（默认“讲义”）与可选要求；运行前可调整，提交后本次参数不可变。
- 表单草稿按 KP/选择集合隔离，切换知识点不能把要求串到另一条；不新增个人处理偏好表。
- 生成完成在当前位置提示。用户仍停留该 KP 且没有主动切到原文时可显示新讲义；其他场景不自动导航。
- “重新生成”沿用相同表单。旧成功讲义一直可读，新讲义归档提交后一次替换；失败、取消不清空旧讲义。

前后文讲义不存在时，按 skill 使用相邻 KP 原文、标题、目录和 blocks/脚注，不禁用生成按钮，也不暗中连带生成前面的讲义。

### 4.4 批量与整本

左栏通过“批量选择”显式进入选择模式，默认没有遍布页面的复选框。选择单元表示该单元全部 KP；全选表示当前教材全部 KP，搜索后必须明确显示是“筛选结果全选”还是“整本全选”。

默认“生成未生成的 N 份”，已成功讲义跳过；覆盖已生成内容必须显式选择“重新生成所选 N 份”，显示替换数量。所有目标、顺序、深度和要求在提交时冻结。

每本教材同时一个活动任务。批量进行时仍能浏览所有原文和已完成讲义；新的生成按钮解释当前任务占用，不另起隐形队列。其他教材不受此限制。

批量逐条处理并逐条提交。普通单条内容/校验错误记录该项失败并继续下一项；来源整体缺失、凭据不可用或运行基础设施不可用停止余项，避免重复失败。最终显示已成功/失败/未执行数量。

取消停止当前真实 PTC run 并停止发起后续项；已提交讲义保留。重试仅新建失败/未执行项的任务，成功项不重跑。第一版不提供“暂停后原样恢复 Agent 对话”的产品按钮；通用 runtime checkpoint 仍保留。

### 4.5 状态与导航细节

| 状态 | 主内容与可用动作 |
|---|---|
| 来源准备/结构排队 | 展示真实状态；成功冻结后可看原文；可取消 |
| 结构运行 | 原文与活动可读；不显示假的 KP 完成率 |
| 结构失败 | 错误原因、查看活动、重试分析 |
| 结构成功且无讲义 | 左栏可浏览；原文默认；生成当前/批量生成 |
| 讲义排队/生成中 | 当前有旧讲义则保留；否则可看原文；显示所在队列位置 |
| 讲义成功 | 阅读讲义、切原文、重做；父级完成数更新 |
| 讲义失败/取消 | 保留旧正文；重试当前或批量未完成项 |
| 页面断线 | 提示“正在重连”，不能改成任务失败；从服务恢复快照与活动 |
| 无权限/旧链接 | 明确说明并给可用返回入口；不显示其他家庭资产 |

用户选择 KP、视图及正文内原文跳转可深链；选择操作写入浏览器历史，目录展开、搜索输入和活动流更新不制造历史条目。前进/后退恢复选择、视图和各正文滚动位置，返回列表保留列表筛选。

原文范围采用 1-based inclusive。anchor 已是 source_lines 坐标时不再减 line_offset。全文 Markdown 渲染用 AST 源行位置关联块，跳转定位并高亮范围；不依赖生成 HTML 的行号。讲义与原文滚动分别保存，返回讲义回到原位置。

跨知识点 Markdown 相对链接通过当前结构/材料映射转为工作台选择；目标讲义未生成时打开该 KP 原文及生成入口，不产生 404 或偷偷启动任务。普通网页链接沿用站点既有外链行为。图片、标题长文本、搜索无结果、键盘展开/选择和触屏目标都纳入验收。

## 5. 源文件、skill 与 PTC 边界

仓库打包 plugins/langalpha_local/skills/more-to-skills/，保留上游 MIT 署名；运行不依赖宿主机个人目录。固定 skill/schema 的内容摘要随任务保存。同名技能版本被修改也能区分。

图书馆现有解析 bundle 是输入。复用快照服务的安全读取、摘要校验和必要私有归档逻辑，改掉旧 version_id/多来源 position 约定；不重复 OCR，也不重新生成图片。源快照保持 Markdown 原始字节和图片相对布局，后续图书馆再次解析不改变已绑定教材。

~~~text
/managed/textbook-job/<execution-id>/
  inputs/                         固定 Markdown、图片、结构/blocks、已需用讲义
  .agents/skills/more-to-skills/   固定技能及 schema
  work/                           可新建、复制、调整的脚本及中间结果
  outputs/<book-slug>/            skill 原生产物
~~~

每次实际执行使用独立 execution-id，并显式映射 job/item/run/attempt；不再从路径末段猜测业务 job_id。执行之间的数据通过已提交产物恢复，不以旧 sandbox 目录仍然存在作为前提。

允许正常 Bash、ExecuteCode、Read/Write/Edit 和实际图片读取能力；Agent 可以复制技能脚本到 work 修改后执行。既有教材 Bash 已允许普通命令，不另建白名单解释器。不在中间文件 Write 时要求最终 schema 成立。

只有一份教材执行配置；默认不注册旧 textbook-chapter-worker，也不为此新造多个教学人格。技能需要的信息由任务输入提供，父账户模型配置沿用现有配置解析，普通 PTC 的 subagent/MCP/Skills 能力不受影响。

新 managed_execution.kind 统一为 education_book，任务的 structure/materials 差异仅放业务输入。执行超时、恢复和清理都识别这一类型，不继续接受旧三种 kind 作为运行时 fallback。

结构任务执行 Structure Only。材料任务执行 Reading Material Only，结构 ID/锚点只读；输出 JSON 只能作为目标 KP 的材料关联来源，不能整份覆盖已导入树。新增覆盖观察和提示保留在任务报告，不能借材料生成偷偷改树。

blocks.json 是后续精确取块、图片和脚注的必要持久辅助产物，随结构保存；重暂存时只按来源清单重建 resolved_path，不改变块编号和锚点。文件路径、资产清单与存储哈希由服务计算。

服务端按固定 schema 验收，不能使用任务修改后的 schema/校验脚本决定通过。内容标准就是 schema 与本任务要求的 nodes、knowledge_points；另检查 ID、引用、行号边界、文件存在性和路径，仅保障可入库和可读取。不新增 LLM 评分或无限修复外循环。

JSON 解码拒绝重复对象键、非有限数值及不受支持的 schema major，避免解析器静默覆盖字段或到 JSONB 写入时才失败；错误定位到文件/字段，不回退到旧格式解析器。

真实样例的已有检查为 296 nodes、112 KP、2 份讲义、5977 源行。两处 title_source:null 曾违反枚举且原报告跳过 jsonschema；实施时重验最新文件，保留精确错误，不放宽 schema，也不直接改用户样例。

## 6. 数据模型与唯一事实来源

三类核心教材产物仍是 structure、KP、material；除此之外必须有教材身份、任务记录和学生授权，不能用“三张表”掩盖这些真实需求。

| 表/记录 | 作用与唯一性 |
|---|---|
| education_textbooks（重建字段） | 家庭/名称/唯一固定来源描述/current_structure_id，不保留 versions |
| education_book_structures | 不可变语义 JSONB、schema/skill 摘要、源与 blocks/报告引用 |
| education_book_knowledge_points | 查询投影：UUID、structure_id、skill KP ID、序号、KP JSONB；同结构 KP ID 唯一 |
| education_book_materials | 每 KP 一份当前成功材料引用/哈希/生成参数/任务 ID |
| education_book_jobs | 请求目标、幂等键、操作、状态、计数；每本书至多一个活动任务 |
| education_book_job_items | 一个结构执行、一个 KP 执行或明确要求的附加材料执行；状态、run/thread/workspace、attempt token、租约、候选产物清单 |
| education_book_activity_events | 有界公开活动、持久游标、去重 ID；不是执行状态真值 |
| assignments / learning state | 既有学生授权、进度、笔记、学习空间表改接新引用，不依赖 publication/revision/Unit 表 |

递归 nodes 只保存一次，不新建目录节点关系表。KP JSONB 保留 unit/nodes/blocks/扩展字段，多节点关联不压成单个 node_id；派生查询字段由代码生成。

纠正第一版的多处可变 content_file：material 记录是“当前讲义”的唯一可变事实源。原始结构/原始 KP JSONB 留作语义与生成证据，API 和导出 book-structure.json 从 material 记录合成当前 content_file；不同时修改结构 JSON、KP JSON 和存储文件三份指针。归档的原始 JSON 是只读证据，当前导出是确定性投影。

首批导入若已有合法 chapters，按同样材料归档流程建立 material；chapters 为空不影响结构完成。只导入受控目录中实际存在且关联明确的文件。KP/title/anchor 不因讲义重做而改变。

首次结构导入原子提交结构、KP、教材 current_structure_id、任务成功状态与业务活动事件。材料对象先写入本次 attempt 的不可变路径，再事务更新当前指针、item 结果和完成活动；不会先显示“成功”再补文件。

对象存储与 PG 不假装是同一个事务：上传前持久记录候选键清单；上传失败不更新当前指针，数据库提交失败留下待收尾候选。恢复按已记录键/摘要核对，已提交结果只补收尾，不重新生成；未提交候选只能在当前 attempt 仍有效时提交，否则清理。

## 7. 执行、重试与恢复

一个结构任务对应一个 item 和一次正常 PTC root run。材料批量任务包含按 schema 顺序排列的 item，每个 item 对应一条 KP 的 root run，依次执行；输入含上条已成功材料或技能规定的原文替代上下文。这是任务调度边界，不在 skill 内增加自定义 JSONL/manifest 协议。

为保证“第一份完成即可读”，第一版不把整本所有讲义塞进一个直到最后才 finalise 的超长 root run。全部讲义按钮组合“结构分析 + 所有 KP item”；附加 glossary/patterns/cheatsheet 只有用户明确要求时由材料任务的末项处理，不阻塞结构和讲义阅读，不强制每本生成。

需要后续全书生成时，在结构导入及当前 job 完成的同一事务内建立唯一后续 materials job/items，由持久队列唤起。附加材料 item 与 KP item 的计数分开；已有全部讲义而附加文件失败时，明确显示“讲义已就绪，附加文件失败”。

job/item 业务状态与 runtime ledger 分工明确：runtime RunCoordinator 决定实际运行终态；教育 finalizer 根据终态验证/提交教材产物。租约/attempt token 条件更新阻止取消、旧 run、重复回调和跨 worker 迟到结果覆盖新内容。

队列持久化后可以立即唤起执行；恢复扫描同样能拾取未启动项，不能仅依赖请求中的后台协程。reconcile 接入服务维护/恢复周期，查询 PG 与 runtime ledger，不用进程内字典判断存活。模型层的既有有限瞬时重试保留；最终 schema 失败不自动新建无限业务任务。

服务重启：已提交项保留；已结束且有可验证产物的项执行幂等 finalise；确实中断且不能由 runtime 安全恢复的项标为可重试，并停止该批后续项，界面明确说明。不能把无心跳直接当模型失败或自动重做已完成项。

材料引用时携带 structure_id 与 KP ID。历史不用保留不等于可以删掉执行 fencing；同一编号也不能让迟到任务写进别的结构。

## 8. Timeline 容量与重连

在正常 PTC 运行事件进入 compact accumulator/Redis 之前，提取工具开始/结束的短摘要及公开工作说明；普通聊天的 full profile 不变。不要把原始思维链、token delta、完整代码和工具参数/结果送入教材活动流。

活动接点应在可 await 的流消费边界，不能在同步格式化函数里 fire-and-forget 写数据库。业务含义与筛选留在 education 模块，核心仅提供通用可选回调。可选 `report_progress` 只补充长工具调用的公开说明，没有它也能正常完成。

`report_progress` 的发送端不是 `more-to-skills` 本身。平台只向教材托管 PTC root Agent 注入一个受限的 `report_progress(stage)` 工具；教育 managed task contract 按 structure/material/supplementary 给出少量允许阶段，Agent 在真正进入阶段时主动调用。工具只写 LangGraph custom stream，不访问数据库，不接收业务 ID、完成数量、文件路径、教材正文或自由展示文案。education observer 校验阶段并映射用户文案，未知阶段直接忽略。

活动分三层权威：服务端 job/item 生命周期和产物提交是业务真值；Agent 语义进度只解释“当前在做什么”；通用工具开始/结束只作为可展开明细。`已完成 N/M` 必须来自已提交 item 的数据库计数，不能从模型上报、工具事件或文件写入推导。详细契约见 `docs/plans/2026-10-02-managed-textbook-progress-design.md`。

普通活动初始预算为每任务最多 1000 条/1 MiB，单条序列化不超过 2 KiB、说明最多 512 字符，同一活动更新至少合并 1 秒。达到预算后停止详细活动，更新计数摘要；任务及每 item 的唯一终态仍记录。完成事件数量受冻结的 item 集合限制，不能由模型无限制造。预算是代码默认值，压力验收后可调，不加入用户配置页面。

PG 是活动回放与任务快照来源，Redis 只作有界通知/缓存；只保留这一份教材 ledger，不继续写旧 JSONL/进度表。终态与业务提交同事务，通知丢失可从 PG 补齐；活动写入临时失败显示“活动暂不可用”，不能伪装任务失败或成功。

工作台先取状态和高水位游标，再订阅 after_seq；期间事件不能丢失。重连/换 worker 去重补齐；后台标签页可断流，回到前台重新读快照。超过保留范围时要求刷新快照，不能无限重放。SSE 无法连接时有限退避轮询状态，不重启每 KP 的 2 秒查询风暴。

工作台时间线以服务端里程碑为主线，每个运行中 item 只突出一个当前语义阶段；重复 Read/Bash 等活动收进可展开明细。结构事务提交前不显示假的知识点完成率；材料批量的完成数只统计已提交的知识点材料，附加材料单列。OCR/解析属于图书馆文档服务，只能作为已完成的来源里程碑，不能伪装成当前教材 Agent 阶段。

任务成功只表示这次请求目标完成；教材头部始终分别显示结构状态和成功讲义数量。当前模型思考/工具运行显示状态和耗时；只有真实已提交项才进入 N/M 完成数。

## 9. 学生端与跨模块接线

工作台“给学生使用”选择家庭学生，创建最小 assignment/grant；不需要再逐 KP 审批、发布结构或创建 publication snapshot。默认不自动分配。

学生可浏览已授权教材结构与原文、已有成功讲义；未生成项显示“讲义尚未准备”，没有 PTC 生成按钮。后来成功生成/重做的材料对已分配学生可见；撤销授权后读 API、图片、活动和 Flash 上下文均需重新校验。

进度/笔记/总结用 structure 内的节点 ID 或 KP UUID 关联，不能再查询旧 units 表。保留现有学生功能入口，只改其读取契约，不增加家长加工层级。

Flash 追问仍在学生私人工作区，由服务绑定授权教材/知识点并读取当前成功材料。每一轮冻结当时材料的内容摘要/引用，避免之后讲义替换改变已发消息的依据；客户端不能注入其他教材材料。旧 learning_spaces 清理前处理其专用会话，不能删除映射后让旧受限会话变成普通自由会话。

图书馆 teaching-usage DTO 改为教材 ID/名称、固定来源、结构状态和讲义计数，链接直达工作台；删除 content_version/publication/book_asset_manifest 的旧展示。原文/图片资产鉴权继续复用现有服务，输入快照独立于图书馆重新解析。

## 10. 清理与切换原则

详细范围见清理清单；它是实施验收内容，不是“上线后再顺手清理”的待办。

旧教材生产与消费调用、表/列/约束、前端路由/懒加载/API/query keys/类型、图书馆反查、学生服务、PTC 专用 worker/managed kinds/配置、staged progress helper、测试与运维脚本都必须闭环。

旧迁移文件和历史 CHANGELOG 作为历史链保留，不改写已应用迁移；新迁移产生完整新 schema 并清理旧教材 schema。不能重复 075 的根表 TRUNCATE ... CASCADE。开发可隔离构建新组件，但发布只允许一次完整切换，不在运行时保留新旧教材引擎选择开关。

切换窗口暂停旧教材入口并清退准确的活动任务；用旧记录导出准确清理清单后再删表。服务拥有的 sandbox/workspace/thread、Redis run key、教育派生对象按确认归属精确收尾；不扫描/清空整桶、不删除普通工作区、图书馆输入、家庭或作业数据。

切换前在隔离 PG 验证空库到 head、旧 head 到新 head、真实外键、学生授权和图书馆使用查询。一次性应用迁移并同步后端/前端，旧链接显示重置说明。失败回退代码不能恢复已删除历史数据，该事实明确记录；原始图书馆资产仍保留，可重新加工。

## 11. 验收门槛

- 从完成解析的图书馆条目到结构可浏览，只需选来源/添加并分析，不需建版本、接受候选或发布。
- 教材列表进入即工作台；选 KP、看原文、生成/重做、查看活动、批量重试不离开工作台。
- 结构-only、直接生成中间 KP、批量部分失败、取消、刷新/重连、worker 重启、重复请求均有自动化和真实行为证据。
- 图片可供模型真实读取、前端授权渲染；原文行号正确，相对讲义链接不产生死链。
- 保留的学生笔记/总结/进度/追问和图书馆教学使用情况不再依赖旧表。
- Redis/PG/浏览器端同时通过 150001 delta 及大量短工具事件压力检查；不是只在前端隐藏。
- 清理清单中删除项没有生产 import/SQL/路由/query key/动态配置残留；保留项无需为了兼容旧 schema 多态分支。
- 前端仍监听 0.0.0.0:5177 并通过 LAN 实测；普通 PTC、Flash、图书馆解析、家庭与作业回归通过。
