# more-to-skills 教材处理重构设计

日期：2026-09-30。状态：根据用户已确认边界整理的设计；本轮仅编写文档，不实施代码、数据库或运行服务变更。

## 已确认的产品边界

- 以用户更新后的 `more-to-skills` SKILL.md、SPEC.md 和 schema 为内容及格式依据，接受现有知识点颗粒度，不增加细分标准、不改写技能的教学模板。
- Structure Only 默认完成 nodes 和 knowledge_points；Reading Material Only 可以直接处理任意知识点，前文不存在时采用技能规定的原文和相邻结构上下文。
- 讲义就是 `chapters/<kp.id>-<slug>.md`，不再叠加旧的讲义二次加工、自动判题包、候选点审阅和用户手动拆分流程。
- 旧教材派生数据及其偏好无需保留，允许重建不合理的教材表；不为旧流程保留兼容读写分支。
- 输入来自图书馆已经处理好的 Markdown 和关联图片；不重复 OCR、解析原书或生成已有图片。
- Agent 可以在 Docker 任务目录内编写、修改、执行辅助脚本。不能用固定脚本白名单替代 PTC 的编程能力。
- 简化配置；普通 PTC、Flash、Skills、MCP、SSE、checkpoint 与学生/家长权限边界仍然保留。

## 主流程

```text
图书馆解析结果：Markdown + 图片
        ↓ 固定一个解析产物快照
PTC + more-to-skills：Structure Only
        ↓ book-structure.json（nodes + knowledge_points）
服务端 schema 校验、来源绑定、事务入库
        ↓
目录 / 知识点 / 原文浏览
        ↓ 用户选中知识点，附带生成要求
PTC + more-to-skills：Reading Material Only
        ↓ chapters/<kp.id>-<slug>.md
服务归档并关联知识点 → 查看讲义
```

整本生成是上述操作的组合。结构成功后立即可浏览，不等待讲义；一份讲义失败不回滚已导入结构和其他已完成讲义。默认顺序生成选中的知识点，先不增加并行调度和共享 JSON 合并系统。

## skill 与服务的职责

技能随项目打包到 `plugins/langalpha_local/skills/more-to-skills/`，保留其 MIT 许可及上游署名。个人目录是本次导入来源，不是生产运行依赖。交付所使用的技能版本、schema 及代码摘要随任务记录，避免同名版本被修改后失去可追溯性。

任务启动时只提供来源、输出目录、操作模式、选中的 KP ID、深度和用户要求。使用系统已有模型配置，不新增教材专属模型、Agent 人格和多层 processing profile。

技能负责内容分析、脚本辅助处理和生成原生产物。服务负责来源读取、任务调度、固定 schema 验收、事务入库、资产访问与事件推送。不要求模型生成数据库 ID、SQL、对象存储清单、哈希或几套内容相同的 JSON。

Agent 可在 `work/` 编写新脚本，也可以复制随技能提供的脚本后修改运行。固定的服务端 schema 不随某次任务的修改改变；Agent 输出的 schema 副本和 validation-report 是产物，不是服务端的验收权威。

现有 `_build_managed_policy_tools` 对教材任务已不使用旧的小型 Bash 语法限制；保留正常 Bash/ExecuteCode/Read/Write/Edit 能力，不因看到未使用的 validator 而另建执行引擎。

## 单一目录和输入资产

```text
/managed/textbook-job/<job-id>/
  inputs/                         冻结的 Markdown、图片、已有结构和材料
  .agents/skills/more-to-skills/   本次固定技能版本
  work/                           自编/修改的脚本与中间数据
  outputs/<book-slug>/
    book-structure.json
    book-structure.schema.json
    validation-report.md
    blocks.json
    chapters/
```

保留现有 `outputs` 写区，通过技能支持的输出根覆盖指定路径；明确技能根路径，避免依赖宿主机 WorkBuddy 安装位置。删除旧 book-skill、knowledge 等专用目录模板。

原文暂存不改动行数与正文图片引用；将图书馆关联图片按原相对路径提供给 sandbox。前端经授权的资产接口解析图片地址，不把对象存储凭据或 sandbox 绝对路径交给客户端。讲义使用的源图片继续引用已有资产；确有新产物才归档到该任务的 `education/` 前缀。

第一版一个结构绑定一个图书馆 Markdown 解析产物，符合 schema 的单源坐标系，不增加多源合并协议。原文版本固定后只读，不允许因清洗重写使已有行号失效。

## 最小数据库模型

实现时优先收敛为三类教材业务记录，复用必要的教材身份、来源绑定、通用任务/attempt 和事件机制：

| 记录 | 内容 | 约束 |
|---|---|---|
| book structure | 教材/来源快照 ID、完整结构 JSONB、schema/skill 摘要、归档位置 | JSONB 原样保留递归 nodes、coverage、未知扩展字段 |
| knowledge point | structure ID、skill 的 KP ID、顺序、原始 KP JSONB | `(structure_id, kp_id)` 唯一；unit/nodes/blocks 保留技能语义 |
| material | 所属 KP、当前讲义文件引用、摘要/大小、生成任务 ID | 一份当前可用讲义；不建用户可操作的历史版本系统 |

章节树直接来自结构 JSONB，不再维护第二套单独节点表及通用内容树协议。KP 行用于定位、任务关联、学生学习入口；它是服务从 JSON 确定性生成的查询投影，不让模型双写。

`knowledge_points[].nodes` 允许多个引用，保留数组，不压缩成一个 content_node_id；节点 ID 在同一结构内解释。可选字段仍按 schema 处理，不引入必须有 confidence、summary、point_type 等旧约束。

入库在同一事务保存结构和 KP 投影。讲义归档后，在同一事务更新对应 material 和 JSONB 中该 KP 的 `content_file`，不替换其他 KP 的内容指针。对外导出的 JSON 从当前已提交记录生成，不维护第二份可变的“权威 JSON”。最初的生成文件作为只读任务产物留档。

取消用户手动拆分、合并、细化、候选审阅，不引入增量结构编辑及跨版本 KP 对齐。内部 structure ID 仍区分不同生成结果，防止延迟返回的旧任务写入新结果；这是执行一致性，不是历史版本产品。

最终 DDL 在实施第一步核对外键后列出精确清理清单。历史数据可删除的授权限于旧教材处理数据；图书馆原文/图片、账号、家庭、作业及普通 Agent 数据不在清理范围。删除教材表前解除明确引用，不使用宽泛 CASCADE。

## 验收与失败处理

内容验收标准是固定 schema，以及本产品结构任务要求的 nodes 和 knowledge_points；不额外评判教学颗粒度，不增加一套 LLM 内容评分或“达到完美后才能入库”的循环。

服务端同时执行必要的存储完整性检查：ID 唯一、已有引用可解析、锚点不越界且起止有效、输出路径在任务目录内、被导入文件实际存在、任务 attempt 仍有效。这些只保证可存储和可读取，不改变内容标准。schema 允许省略的字段不擅自补成内容要求；无正文可分析时返回明确结果，不伪造 KP。

正式安装 jsonschema 并使用固定 Draft 2020-12 schema，不允许缺库时静默跳过。报告精确 JSON 路径；不在服务层自动改内容或无限重启 Agent。技能内部可以编写脚本和按原规则修复；最终失败保留可诊断报告，由用户选择重试。

2026-09-30 对真实样例的独立检查：19 个顶层节点、296 个总节点、112 个 KP、2 份讲义；原文 5977 行，ID、节点引用和锚点检查通过。两处 `title_source: null` 不满足当前枚举，原报告跳过了 schema 层。实施验收时以届时最新源文件重新检查；若仍存在，向技能流程提供准确错误修复，不能修改 schema 迎合样例，也不修改用户原始样例。

行号按技能的 1-based inclusive 解释；`source_lines` 模式的已生成 anchor 不再减一次 line_offset。需要适配旧区间接口时只在一个边界处转换。原文浏览器同时支持片段查看与带源行映射的全文跳转，图片渲染不改变行号坐标。

## Timeline 与容量边界

保留普通 Agent 事件机制，在教育任务进入 compact SSE 过滤及 Redis 写入之前，将运行事件投影为少量公开活动。不能先写全量 token 到 Redis 再在前端过滤。

公开活动包括任务启动/结束、工具执行开始/结束摘要、Agent 公开工作说明、服务确认的结构导入/材料归档、错误。原始思维链、token delta、完整代码、完整工具参数结果不进入教材 timeline。可选 report_progress 用于长工具调用内的业务说明；没有调用它也不阻止任务成功。

复用一种持久事件记录和顺序游标。PostgreSQL 保存已接受的活动和业务状态，Redis/SSE 提供有界通知/短期回放，重连从持久序号补齐去重。不要再并行保留 JSONL 和另一套业务进度真值。

工具使用 ID 关联开始/结束，同一活动的高频更新合并并限制长度、频率；设置任务事件数和总字节预算，预算达到时合并低优先级工具活动，保留汇总及业务终态。具体数值通过现有 150001 delta 压力用例校准，不承诺每条工具活动都无限保存。心跳不逐条持久化。

只有服务端校验、归档/入库成功后才发“完成”。模型声称已完成、工具退出码 0 和日志缺失，都不能单独决定业务结果。浏览器断开不取消任务；取消必须终止真实运行并由 attempt 校验阻止迟到写入。

## 前端与配置

- 左侧默认按章节分组呈现知识点，并提供原书目录视图；两者不强制混成单一层级。
- 点击知识点可读原文；未生成时显示生成入口，已生成时直接看讲义并可重做。没有前一份讲义不禁用按钮。
- 生成参数只保留技能支持的深度和用户要求；批量操作传 KP ID 列表，不维护另一套加工偏好系统。
- 删除用户拆分、合并、候选审阅和旧阶段 checkpoint 操作，保留真正的运行取消/重试及 PTC checkpoint 机制。
- 学生只访问获得授权的教材与讲义，不获得 PTC 工作区、技能配置、sandbox 或家长任务控制能力。

## 实施顺序与验收链

1. 固定技能与新产物契约，验证真实样例，列清教材专用表/调用点。
2. 完成最小数据模型和直接导入：JSON → 左侧树/知识点 → 原文与图片。
3. 接入统一 PTC 任务：结构生成、任意 KP 讲义生成、选择全部的顺序加工。
4. 接入有界的公开活动事件与断线回放。
5. 切换前端并删除旧生产路径、技能、配置、JSONL 协议及教材专用冗余表。
6. 用真实 Docker、数据库和 LAN 前端验证；每次实质变更写中文 CHANGELOG 并原子提交。

不重新实现 PTC；不迁移旧教材历史；不复制完整教材内容进测试仓库；不在本次设计回合执行删除、迁移、模型加工或服务重启。
