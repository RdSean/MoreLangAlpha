# 平台统一模型额度设计

**状态：已批准（2026-08-14）。**

## 决策

家庭教材加工和无个人模型凭据的 PTC 运行，使用一个部署级的平台模型档案。
首个档案明确引用服务账号 `seanlee.cn@gmail.com` 中已确认可用的自定义
OpenAI 兼容供应商 `silicon` 及模型
`deepseek-ai/DeepSeek-V4-Flash`。

账号凭据继续加密存放在现有 `user_api_keys` 表中。部署只保存非秘密的来源
账号标识和模型名；服务器在需要平台回退时才通过既有 BYOK 解密访问层创建
LLM 客户端。原始 API Key、Base URL 和来源账号身份都不会进入 PTC sandbox、
浏览器响应、教材任务投影或应用日志。

## 方案比较

1. **部署档案引用服务账号（采用）**：环境变量指定来源账号和模型，使用既有
   自定义供应商解析器获取客户端。密钥不复制，撤销和轮换仍由服务账号设置页
   管理。
2. **将 API Key 导出到 `.env`**：会复制长期密钥，轮换容易漂移，且扩大密钥
   暴露面，因此不采用。
3. **将普通家长账号作为每次运行的隐式兜底**：没有明确部署所有权，也无法
   审计或稳定运营，因此不采用。

## 运行规则

- 个人 OAuth/BYOK 继续优先于平台档案，平台档案只处理无可用个人客户端的
  系统目录模型。
- 配置了平台档案时，平台回退始终构造客户端，不再依赖“是否设置 reasoning
  effort”的旧惰性分支；这保证独立教材任务可在没有家长模型配置时启动。
- 平台档案必须同时提供来源账号和模型名。来源账号不存在、BYOK 未启用、
  模型不是该账号的自定义模型或对应供应商无密钥时，解析安全失败，不回退到
  其他用户的凭据。
- `resolve_managed_teaching_agent_config()` 仍以教材所属家长为业务上下文解析
  功能开关，但受控图仍使用 `user_id=None` 创建；平台来源账号绝不成为受控图
  的身份、Workspace、Vault、MCP 或 Skills 来源。

## 部署配置

新增两个非秘密环境变量：

```text
PLATFORM_LLM_SOURCE_EMAIL=seanlee.cn@gmail.com
PLATFORM_LLM_MODEL=deepseek-ai/DeepSeek-V4-Flash
```

生产环境应改用专用服务账号的邮箱标识，而不是个人日常账号。首期本地验收
按已批准的服务账号配置运行。模型配额、并发和任务预算沿用既有平台用量控制；
本设计不把任何凭据写入版本库。
