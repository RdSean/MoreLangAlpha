# 通用工作区前端设计

## 背景

金融运行时、市场路由和价格自动化已经从服务端移除。前端必须同步移除行情中心、财经新闻、TradingView、投资组合和观察列表，避免继续展示不可调用的能力。家庭教育模块尚未具备本地账户和作业 API，本阶段不以静态占位页冒充可用产品。

## 方案选择

采用通用工作区概览作为 `/dashboard`：它保留 LangAlpha 的 Quiet Workspace 视觉系统和既有应用壳层，同时给用户提供可立即使用的聊天、文件和自动化入口。

未采用以下方案：

- 将 `/dashboard` 重定向到聊天：实现快，但失去工作区和自动化的汇总入口。
- 先构建教育首页：会引入没有账户、作业与授权 API 支撑的伪交互，后续必须推倒重做。

## 信息架构

导航保留四个真实可用入口：Dashboard、Chat、Automations、Settings。

`/dashboard` 使用一个轻量级、全宽的工作区概览：

- 顶部命令区提供进入聊天、查看文件、管理自动化三个明确动作。
- 主区显示当前工作区的会话和文件状态，数据继续经现有 FastAPI 与 React Query 获取。
- 不显示行情、新闻、投资组合、观察列表、图表、价格或财经洞察。

教育入口不在本阶段导航中注册；第七阶段在本地账户、家庭成员与作业 API 已可用时，一次性加入角色感知的教育工作台。

## 实现边界

- 复用现有 React 19、Vite、TypeScript、Tailwind、shadcn/Radix 和 React Query；不引入家庭教育项目的 CSS、Supabase 客户端或组件。
- 所有新增视觉表面遵守 `DESIGN.md` 的 Quiet Workspace token、8px 圆角、紧凑信息密度和 Lucide 图标规范。
- 删除市场路由及其懒加载引用，并删除仅由金融 Dashboard 使用的组件、hooks、widget 框架、API 类型和国际化键。
- 与 MarketView 深度耦合的聊天图表/注释能力将在金融代码收尾阶段一并移除；本阶段先断开顶层产品入口，避免大范围重写阻断通用 Dashboard 落地。

## 验证

- Vitest 断言路由和导航中不存在市场、财经新闻或金融 Dashboard 条目。
- TypeScript 编译和前端测试通过。
- 后续教育 UI 任务会单独覆盖家长/孩子角色、作业状态和附件交互，不在本阶段添加模拟数据。
