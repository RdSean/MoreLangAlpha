## 这个技能产出什么

```
output/<book-slug>/
├── book-structure.json          # 主交付物：递归章节树 + 行号锚点 + 知识单元
├── book-structure.schema.json   # 格式的 schema 副本，随数据一起走
├── validation-report.md         # 校验结果（通过也留档）
├── blocks.json                  # 候选块表（Step 3D-a 的中间物，可追溯）
├── chapters/                    # 材料，文件名与知识点 id 或节点 id 对应
├── glossary.md  patterns.md  cheatsheet.md     # 附加材料
```

其中 `book-structure.json` 有**两层视图**：

- `nodes`（必出）—— 穷尽登记的导航树。书上印了几个标题，树里就有几个节点，用来建目录、按锚点回读原文。
- `knowledge_points`（**格式上可选，流程上默认产出**）—— 可独立学习的知识块。粒度不跟层级走：一篇课文可以切两条，词表与词缀链接可以合一条，热身题可以不单独成篇。它才是 Step 7 的交付单位。键本身可省（省了就是纯节点树），但默认会跑。

三层消费者：**① 下游代码** —— 加载 `book-structure.json` 建树、渲染目录；点任一节点，用 `anchor` 的行号区间直接 `sed -n '<start>,<end>p' <源文件>` 切出原文，无需重新解析 PDF。**② 知识点视图** —— 按 `knowledge_points` 分组、计数、逐条勾选生成。**③ 阅读者** —— `chapters/`、`glossary.md`、`patterns.md`、`cheatsheet.md` 是提炼后的附加阅读材料。

**格式定义以 `schemas/SPEC.md` 为准**，本文件只讲怎么跑。若二者冲突，以 `SPEC.md` 为准。

**Preserve the author's precision.** Frameworks often have specific names for reasons. "The 5 Whys" isn't interchangeable with "ask why multiple times." Capture the exact formulation.

**Layer depth appropriately.** Simple books → simple skills. Complex books with 10+ frameworks → skills with reference files and on-demand chapters.

## 可选的宿主进度报告

先按用户范围、来源内容、材料深度和宿主任务声明决定实际工作，再从宿主提供的 `progress` 契约中选择匹配的阶段与可选动作。`allowed_stages` / `allowed_actions` 是可报告的词表，不是必做清单，也不规定顺序。不要为了上报新增例子、练习、词汇板块、图片或额外材料；用户对内容范围的明确限制优先。

当前环境确有契约指定的进度工具时，进入有意义的新阶段或动作可报告一次；同一动作中的连续读写无需逐次报告。动作的 `stages` 和 `when` 决定何时适用，找不到匹配动作可以只报告阶段，也可以不报告。需要返回先前动作时按实际工作报告，不为完成清单伪造步骤。

工具和契约可用时，重要的长时间工作（整理章节树、切分知识点、组织或撰写讲义）优先在开始前报告匹配阶段。先用独立的短工具调用轮次报告并返回，再在下一轮生成长脚本或讲义；不要把报告和大段 `Write`/`Edit`/`Bash` 参数放在同一轮，以免报告等整轮内容生成完才送达。已有小动作不必额外拆轮。不要完成后连续补报几个“正在”动作；遗漏就如实继续，不能倒填时间、推断完成或补齐清单。

没有工具或契约则照常加工，不安装工具、不写 shell 命令模拟事件。工具返回报告不可用时停止后续报告并继续加工，不反复重试，不将报告当作产物、校验结果或提交确认。知识点身份由宿主绑定，工具不接收知识点名称、ID、完成数量或自由文案。

## Modes of Operation

### 1. Full Conversion（默认）
**触发**：用户给出一个或多个文档路径，无特殊说明。
**动作 / 产出**：跑 Step 0–10 → 结构 JSON（+ 知识单元）+ 讲义材料 + 附加材料。
**含不含知识单元**：默认含（跑 Step 3D）。用户明确说「不要切知识点」「只出节点树」时跳过，改成只登记节点树。

### 2. Structure Only
**触发**：用户说「只要结构」「先出 json」「analyze only」「不要讲义」。
**动作 / 产出**：跑 Step 0–6，结构 JSON 通过校验门后即停 → 结构 JSON + 校验报告。
**含不含知识单元**：**默认含**（跑 Step 3D）——3D 本来就在 Step 3 里面，「结构」这一层天然包含 `knowledge_points`。只有用户明确说「只出节点树」「不要切知识点」时才跳过 3D，只登记导航树。
**为什么默认含**：切分省不下多少（每 unit 一次调用，输出只有标题与块编号），但省掉它会让 JSON 与 Mode 1 的同类产物**形状不同**——日后按 Mode 3 补材料时粒度会悄悄退回节点级，等于换了个产品。要省这一步请走显式退出语，不要靠默认。

### 3. Reading Material Only（复用已有结构）
**触发**：用户给出一个已通过校验的 `book-structure.json`，要求补做或重做材料。
**动作 / 产出**：不重跑 Step 0–3 的解析与建树，从 Step 4 确认受众和深度（默认 `讲义`）；Step 7 用已有来源补齐语言/领域判断并按需加载写法 → 材料写回同一输出目录。不能依赖上一任务的模型记忆，也不因缺少 Step 2.1 的判断而重做全书。
**粒度**：可整本重做，也可**只做用户点的那几条**（按 KP 的 `content_file` 是否有值判断做过没有）。**前后文不存在时照常生成**——用上一条的 `anchor` 原文、单元目录与相邻标题补上下文，不要求先补齐前文。

**宿主托管例外**：当宿主提供 `task.json`，且 `delivery.structure_owner`、`delivery.content_file_owner` 与 `delivery.completion_owner` 均为 `host` 时，只生成该任务 `output` 声明的材料文件。`output.root` 只是目录基准，不是额外交付物。结构文件作为只读输入上下文使用，不复制成输出、不回填 `content_file`、不检查其他知识点材料是否存在，也不补做全书。材料关联、结构指针、入库与成功计数由宿主负责；独立使用本 Skill、没有该职责契约时，仍执行下文的回填与结构校验流程。此例外不改变 Structure Only 的结构交付与校验要求。

### 4. Update / Fold-in（增量合入）
**触发**：用户给出一个**已存在的 `book-structure.json`**，并要往里**补录或修正**结构——新解析出来的一段章节、手工整好的节点片段、改正后的区间。
**动作 / 产出**：跳过 Step 1–6，按下面的 **Mode 4 流程**改树 → 重跑校验门 → 只重做受影响的材料。

**与 Mode 3 的区别**：Mode 3 只重做材料、不动树；Mode 4 **改树**。两者的共同前提是既有 JSON 先过 L1。

1. **备份**：`cp "$OUT_DIR/book-structure.json" "$OUT_DIR/book-structure.bak.json"`——改树之前必须留退路。
2. **验既有 JSON 过 L1**；不过就先修。不要在坏树上叠改动。
3. **确认行号同源**：新内容的行号必须落在**同一个 `source`** 的坐标系里。若它来自另一个文件的解析产物，先合并成一份文本，或另起一份 JSON——**不允许往既有树里塞第二套行号**（`SPEC.md` §5）。
4. **定位插入点**：由新内容的 `start_line` 决定挂到哪个父节点下、插在哪两个兄弟之间。**次序的真实依据是坐标，不是 `order`。**
5. **插入**：按 `SPEC.md` §12 的合并规则改树。要点：
   - 已有节点的 `id` **保持不变**（它是 glossary 与 `content_file` 的外键）；
   - 新节点取新 `id`；若插进某个已有兄弟的区间内部，**那个兄弟必须让出这段**（收窄 `end_line`）；
   - 同父 `order` 若取不到「未占用的整数」，就把该父节点下的 `order` 按坐标整体重排或**全部留白**——唯一不许的是重复。
6. **重算包络**：从插入点上溯，重算每一级祖先的 `anchor`。**这是唯一必须动手的一项。**
7. **重跑校验门**，然后**只重做受影响的材料**（新节点 + 区间变动的节点），不要整本重跑。若只是删了节点、没加内容，连材料都不用重做，补一条 `coverage.omitted`（`origin: manual_removal`）即可。

改树 = 人工维护，**任何一步都不许静默覆盖**：新旧内容矛盾写进 `coverage.gaps`，删除的内容在 `coverage.omitted` 留痕。

**改了树之后知识点会失配**：`knowledge_points[].nodes` 引用的就是节点 `id`。删除或重命名过节点后，重跑 3D 或至少跑一次 `validate_structure.py`（L3-10 会报出失效引用）。

### 5. Knowledge Points Only（只切知识点）
**触发**：用户给出一个已通过 L1 的 `book-structure.json`，说「切知识点」「分知识块」「重新切一次」。
**动作 / 产出**：跳过 Step 0–2 与 3A–3C，只跑 **Step 3D-a → 3D-b → 3D-c**，结果合入同一份 JSON（`--merge` 默认替换该 unit 的旧知识点，可反复重跑调参）→ 更新的 JSON + 校验报告。**不生成材料**（那是 Mode 3 或 Step 7 的事）。

## Step 0 — 参数与越界检查

没给任何参数时，停下并回复：

> 「more-to-skills 需要一个受支持的文档路径、目录或通配符。用法：`more-to-skills <路径或通配符>... [books-slug]`」

解析参数：
- 最后一个参数若不是存在的文件/目录/通配符，且形如 slug（小写字母数字与连字符），当作书籍 slug。
- 其余参数是 `INPUT_PATHS`。

**越界检查**：若某个输入路径本身是一个 `more-to-skills` 的输出目录（含 `book-structure.json`），说明用户想复用或更新已有产物。此时不要重跑整条流水线，先确认意图，三选一：

- **只重做材料** → Mode 3（树不动，不重切知识点）
- **往里补录 / 修正结构** → Mode 4（改树，先备份）
- **只重切知识点** → Mode 5（树不动，只重跑 Step 3D；会替换该 unit 的旧知识点）
- **整本重跑** → 会覆盖产物，**必须先明确告知并确认**，不得静默覆盖

## Step 1.5 — 判断内容类型

问用户：

> 「这些素材属于哪一类？这决定抽取方式，不等于学科判断。
> 1. **教材 / 教辅** —— 单元与课时结构，含图表、活动框、练习、词表（语言教材、学科教材、考试教辅）
> 2. **技术类** —— 有代码块、表格、公式（编程书、论文、技术规范）
> 3. **文字类** —— 以散文为主，几乎没有表格与代码（管理、教学法、叙事非虚构）
> 4. **不确定** —— 我用快的方式，质量有问题会提示你」

存为 `BOOK_TYPE`：选 1 → `textbook`；选 2 → `technical`；选 3 或 4 → `text`。

再由 `BOOK_TYPE` 推出**抽取模式** `EXTRACT_MODE`——脚本的 `--mode` 只认 `technical` / `text` 两个值，所以教材要在这里翻译一次：

| `BOOK_TYPE` | `EXTRACT_MODE` | 改档依据 |
|---|---|---|
| `textbook` | `text`，**但源文件是 PDF / DOCX 时改 `technical`** | 教材的表格、活动框、答案页在纯文本抽取里会塌成一串，结构全丢 |
| `technical` | `technical` | — |
| `text` | `text` | — |

- `technical`：提示将用 Docling 做结构感知抽取（保留表格、代码、公式），约每页 1.5 秒。
- `text`：提示将按文件类型选最快的抽取器，Markdown/纯文本通常几秒完成。

两点别搞混：**`--mode` 只影响 PDF 的抽取路径**，对 Markdown / 纯文本没有差别；**`EXTRACT_MODE` 与锚点模式 `anchor_mode` 也无关**——后者只由文件扩展名决定。

### 教材类的三个系统性缺口（`BOOK_TYPE=textbook` 时必须先讲明）

这三处不是解析失败，是格式使然，**在 Step 2.5 的成本预估里就要说清**：

① **图里的文字不在文本里**——信息图、图表、地图上的字是像素，抽取产物只留一行 `![](hash.jpg)` 引用。注意**图片文件本身是真实存在的相对路径，不是占位符**：只要文件与 md 同目录，做材料时可以多模态直读（Step 3 D 会解析并检查文件是否在）。若下游只要 JSON、不读图，这部分内容记 `coverage.gaps`。

② **答案页与 Video / Audio 脚本常整段缺失**（答案单独成册或只在教师版），登记成 `gaps`，不要让段落间凭空出现空白。

③ **目录页会被误当正文标题**——课时名与 `BEFORE YOU READ` / `VIDEO` 在 CONTENTS 里也成行出现，骨架扫描一定命中，归一化时按 Step 3 B 第 1 条剔除。

## Step 2 — 抽取文本与锚点元数据

```bash
"$PYTHON_BIN" "$SCRIPT_PATH" $INPUT_PATHS --mode <EXTRACT_MODE> --install-missing ask
```

产出一次性工作目录（默认 `<临时目录>/more_skills_work-<pid>/`，可用 `MORE_SKILLS_WORKDIR` 指定）：

- `full_text.txt` —— 所有源文件的合并正文，各源之间有 SOURCE 横幅分隔。
- `metadata.json` —— 总体统计 + 每个源的详情。

**从输出里读三行路径**（`Workdir ->` / `Text ->` / `Meta ->`），不要假设固定位置——目录名带进程号，正是为了并行抽取互不覆盖。

### 锚点元数据（v2.0.0 新增）

`metadata.json` 里每个源都带下面这些字段，**它们是锚点方案的前提，不要跳过**。写入 `book-structure.json` 的 `source` 块只需要其中前 5 项：

| 字段 | 含义 | 进 `source` 块 |
|---|---|---|
| `total_lines` | 锚点坐标系的**总行数**（≡ `sed -n '<N>p'` 的行号口径，比 `wc -l` 可能多 1） | ✅ |
| `anchor_mode` | `source_lines`（Markdown/纯文本/RST/AsciiDoc，逐行原样抽取）或 `workdir_lines`（PDF/DOCX/EPUB/HTML，没有稳定的原文行号） | ✅ |
| `line_offset` | **原文件行号 = full_text 行号 − line_offset**。仅 `source_lines` 有意义 | ✅ |
| `source_total_lines` | 原始文件行数。与 `total_lines` 不一致说明抽取时清洗动过行结构，锚点会错位 | ✅ |
| `workdir_text` | `full_text.txt` 路径，`workdir_lines` 模式下锚点实际指向它 | ✅ |
| `text_start_line` | 该源正文在 `full_text.txt` 里的起始行 | ⬜ 仅供你换算 |
| `filename` / `format` | 文件名与格式 | ⬜ 可复制 |

**生成方不需要自己推算 `line_offset`** —— 它由抽取脚本写进 metadata。实测单源 Markdown 为 4；多源时每个源各不相同（第 2 个源通常不是 4）。

⚠️ **多源输入与单源格式的冲突**：本格式一份 JSON 只有**一套**行号坐标系（`SPEC.md` §5）。若用户一次传了多个文件，`full_text.txt` 里是拼接结果、各源偏移不同，**不要**把拼接线之后的锚点写进 JSON。两条出路：先合并成一份文本，或分别跑、各出一份 JSON。

### 确认抽对了文件

动手生成任何东西之前，核对 `metadata.json` 里的 `filename` / `source_file`，或 `full_text.txt` 第一行的 `SOURCE:` 头。等待后台运行时，要盯**那一次运行自己的** workdir——盯共享路径可能读到另一次运行的结果。

### 环境预检

`"$PYTHON_BIN" "$SCRIPT_PATH" --check` 会打印每种格式的抽取器安装情况与确切安装命令，不处理任何文件。用户报环境问题或抽取质量问题时先跑它。

## Step 2.1 — 识别原文语言，再判断学科或领域

抽取并核对来源后，利用已有标题、目录与少量代表性正文先识别原文语言（中文、英文、其他或混合），再判断学科/领域及主要学习目标。宿主已提供解析原文时直接使用，不重新抽取；大书也只取必要片段，不为识别读入全文、联网或另开专门规划轮次。

原文语言、学科和讲义语言是三件事：中文数学与英文数学都以数学理解为目标；中文叙事可能是语文阅读，也可能是历史材料，需结合课文任务和上下文判断。`BOOK_TYPE` 只是抽取类别，英文标题、`Task` 或词框不能代替领域判断。跨领域/双语内容保留实际混合目标；依据不足时只确认已知部分，不凭书名断定全书目标。

判断作为本次工作上下文，供后续组织内容使用，不新增结构字段、分类文件或数据库写入。**本步骤与结构分析阶段不加载讲义模板**。只生成材料的 Mode 3 在 Step 7 用目标原文和已有结构完成同样判断，不重跑本步骤；附加材料沿用其自身任务范围，不为套模板额外生成讲义。

## Step 2.5 — 成本预估（生成前必做）

读本次的 `metadata.json`，在做任何生成之前给用户预估：

```
📖 源文件 <N> 个：<逐个列文件名与格式>（若 images_dropped > 5，提示有 N 张图未被读取）
📄 合计：约 <N> 页/节 | <N> 词 | 约 <N>K tokens
💰 预估成本
   ① 结构 + 切分（必跑）：输入约 <N>K + 输出约 <N>K ≈ <N>K tokens　⏱ 约 <N> 分钟
   ② 逐条讲义（可分批）：约 <N> 条 × 单条 <N> tokens ≈ 输出 <N>K tokens
📁 将生成：book-structure.json（含 knowledge_points）+ chapters/ + glossary.md + patterns.md + cheatsheet.md
➡  开始吗？（回复「只要结构」＝ 结构 + 知识单元，不出材料；「只出节点树」＝ 连知识单元也不切）
```

**怎么估**：

- **① 结构 + 切分**
  - 结构：输入 ≈ `metadata.estimated_tokens` × 1.3；输出 ≈ 结构 JSON 约 3,000（含知识点标题）
  - 切分：输入 ≈ 正文总 tokens × 1.2（按 unit 分次喂块），输出很小（只有标题与块编号）
- **② 逐条讲义** —— **条数在切分跑完之前只能粗估**，跑完 3D 会给出准确值，届时回头修正预估。粗估用：
  - `KP 数 ≈ 正文行数 ÷ 45`（教材实测：Unit 1 的 476 行切成 11 条）
  - 单条输出按深度档：`摘要` 约 800 / `讲义` 约 3,500 / `精讲` 约 7,000 tokens
- 成本**报 token 数，不写死金额**——单价与模型名变动频繁，要举例就标日期并注明是估算。

**默认策略：切分跑全量，生成按需/分批。** 切分便宜（只有标题），生成贵且可断点续跑——用户可以勾哪条生成哪条。Step 2.5 要把这个选择摆到台面上，不要默认一次跑完。

等用户确认。三种回话对应三条路：

| 用户回话 | 走法 |
|---|---|
| 「开始」 | Mode 1，全量跑（结构 + 知识单元 + 材料） |
| 「只要结构」「不要讲义」 | **Mode 2，第 ① 段全跑**——结构 **+ 知识单元切分**，不出材料 |
| 「只出节点树」「不要切知识点」 | Mode 2，但**跳过 3D**，只登记导航树（省一次切分，代价是日后补材料会退回节点粒度） |

## Step 2.6 — 大书用 REPL 式访问（> 50k tokens）

把 `full_text.txt` 当可查询语料，而不是一次读完。整本读进上下文会烧掉后面生成要用的预算。

```bash
wc -l "$FULL_TEXT_PATH"                                   # 先看规模
grep -n -E "^\s*(#{1,6}\s|UNIT|CHAPTER)" "$FULL_TEXT_PATH" | head -40   # 找位置
sed -n '<start>,<end>p' "$FULL_TEXT_PATH"                 # 只取需要的片段
grep -c -i "<关键词>" "$FULL_TEXT_PATH"                    # 断言某事确实被提到
```

`<50k tokens` 的书一次读完即可。一本 200 页的书约 75k tokens，逐章重读一遍（28 次）要烧掉约 2M 输入 tokens；用 grep + sed 只取片段，成本与**输出**成比例，而不是与源文件成比例。

## Step 3 — 结构分析 → `book-structure.json`

宿主提供进度契约时，可按上面的可选报告约定说明真实的结构处理阶段；仅使用本任务允许的词表。

**这是本技能的核心。** 目标产物是一个**递归的、每节点带原文行号锚点的章节树**，格式见 `schemas/SPEC.md`，机读定义见 `schemas/book-structure.schema.json`。

### 三步闭环

**A · 骨架扫描（脚本，确定性）**

```bash
"$PYTHON_BIN" "$SKILL_ROOT/tools/scan_outline.py" "<源文件>" --json "$WORKDIR/outline.json"
# 输入是 full_text.txt 时补 --line-offset <metadata 里的值>
```

脚本逐行抓「像标题的行」——Markdown 井号标题、setext 标题、编号式标题（`UNIT n` / `CHAPTER n` / `第N章` / `第N节` / `Capítulo n`）、课时标记（`Reading A` / `Video`）、板块标记（`WARM UP` / `BEFORE YOU READ` / `VOCABULARY PRACTICE` 等）、独立全大写行——并输出：

- `candidates[]`：行号 + 原文 + 清洗后文本 + `kind` + `hint_level` + `marker`
- `page_markers[]`：`{N}----` 形式的页码分隔行，可用于校验 `page_range`
- `suspicious[]`：疑似正文被误析为标题的长条目

**这一步只找位置，不做判断。** 锚点因此天然精确。**不要自己数行号。**

**B · 语义归一化（模型）**

读骨架（不是读全文）＋ 目录页线索，做这些判断。**先翻一遍 `reference/parsing-traps.md`**——PDF→MD 产物的 P1–P7 通病（板块标题被降级成段落、图注粘标题、层级不稳……）在那里，识别不出来就会错建或漏建节点。

1. **定层级**：哪些 `hint_level` 可信、哪些是噪音。典型噪音：
   - **目录页里的条目**。书的 CONTENTS / SCOPE AND SEQUENCE 段落会把章名、`BEFORE YOU READ`、`VIDEO` 之类当正文列出，扫描器会命中它们——它们**不是**结构。
   - **图注、练习短文标题被误析为标题级**。这类不做节点：没人主动决定跳过它 → `coverage.gaps`；你判断它不值得建节点 → `coverage.omitted`（`origin: low_value`）。
   - 正文里的全大写强调句（`hint_level` 为 `null`）。
2. **定层级名称**：写 `level_names`。教材 `["unit","lesson","section"]`，专著 `["part","chapter","section"]`，论文集 `["section","chapter","article"]`。映射建议见 `SPEC.md` §6.3。
3. **定 `type`**：按**内容性质**给，不按层级给。推荐清单只有 6 个值（`front_matter` / `body` / `exercise` / `reference` / `back_matter` / `other`），见 `SPEC.md` §6.1。**清单外自制也合法**——不要为了凑清单把"信息图板块"硬说成别的。
4. **补丢失的层级**：解析产物常把某级标题整个吃掉。若某节课的标题在正文里不存在，按其与相邻板块的边界**合成**一个节点，并设 `title_source: "generated"`，在 `notes` 里说明合成依据。
5. **定编号**：`number` 用原书印刷编号（字符串，原样保存）。**编号常常只存在于目录页**，正文标题只有主题名——此时按目录顺序推导，并在 `coverage.gaps` 里记一条说明。
6. **填锚点**：
   - `start_line` = 该节点自身标题所在行（标题丢失时取能确定的最早内容行）
   - `end_line` = 下一个兄弟开始前的最后一行；最后一个兄弟取父节点结束前的最后一行。注意排除下一页的 `{n}----` 分隔行（P7）。
   - **父节点的锚点按子节点重算包络**，不要沿用标题行原值——真实数据里手工记的父区间经常不包含子区间。
   - 确实划不出可信区间时，**不要伪造**：记进 `coverage.gaps`。
   - `level` / `order` 可以留白（按嵌套深度与数组顺序推导）；**但锚点必须给**，它是唯一的硬要求。
7. **标 `processed`**：结构应**完整登记**，但只有被要求处理的节点才 `processed: true`。用户说「只处理 Unit 1–12」，就登记全书、只把 Unit 1–12 标为已处理。

> **几十个以上的节点就别手写。** 写个一次性脚本按骨架产出草稿再人工校正——手工列表必然会错行号，而锚点是唯一不能错的字段。

**C · 校验门（脚本）**

```bash
"$PYTHON_BIN" "$SKILL_ROOT/tools/validate_structure.py" \
  "$OUT_DIR/book-structure.json" \
  --out-root "$OUT_DIR" \
  --report "$OUT_DIR/validation-report.md"
```

实现 `SPEC.md` 第 8 节的三层规则，**只有 L1 会阻断**：

| 层 | 查什么 | 影响 |
|---|---|---|
| **L1 格式门** | 能不能解析、有没有 `title`、有没有一个说得通的范围（`1 ≤ start ≤ end ≤ total_lines`）、字段类型；`knowledge_points` 给出时的形状（L1-13） | ✅ 阻断 |
| **L2 一致性** | `id` 唯一、同父 `order` 唯一、`level` 与嵌套深度一致、兄弟不重叠、子区间含于父区间、`order` 与坐标同序、同 unit 知识点不重叠（L2-10） | 只报告 |
| **L3 提示** | 覆盖率、未登记的缺口、`content_file` 缺失、`type` 不在推荐清单、知识点覆盖率与引用失效（L3-09 / L3-10）…… | 只报告 |

退出码：`0` = 无 L1；`1` = 有 L1；`2` = 用法/IO 错误。**L2 / L3 永远不阻断**——解析质量差的书不该因为"结构不够漂亮"而处理不下去。

- **L1 通过** → 复制 `schemas/book-structure.schema.json` 到输出目录，进 Step 4（若要切知识点，先跑下面的 D）。L2 / L3 的报告留下来，在 Step 10 简报里如实转述。
- **L1 不通过** → 按报告里的规则号与节点 `id` 定位，回到 B 修正，最多 **3 轮**。
- **3 轮仍不过 L1** → **中断本次运行**，写出 `book-structure.partial.json` 与失败报告，**不要进入 Step 7/8**，并明确告知用户原因与违规清单。L1 只查格式，连过 3 轮不过通常说明拿错了文件或行号口径不对，值得停下来看。

### D · 知识单元切分（Step 3D，**默认跑**）

**目标**：把书切成「一个学生能独立学完的知识块」，写进 `knowledge_points`。**粒度不跟层级走**——同一单元里，一篇课文可以切两条，词表与词缀链接可以合一条，热身题可以完全不单独成篇。用「取第 N 层」这类规则表达不了这件事（`SPEC.md` §6.5）。

**必须排在 C 之后**：`knowledge_points[].nodes` 要引用节点 `id`，树没定稿就没 id 可挂。

三步的形状与 A/B/C 完全同构：**脚本出骨架 → 模型做选择 → 脚本兜坐标**。模型**从头到尾不输出行号**。

**3D-a · 分块（脚本）**

```bash
# 一次全量分块，块编号按全文件计（后续按单元渲染不会冲突）
"$PYTHON_BIN" "$SKILL_ROOT/tools/split_blocks.py" "<源文件>" \
  --json "$OUT_DIR/blocks.json"
```

产出 `blocks.json`：块编号 + 行号区间 + `kind` + 脚注定义 + 图片路径。它顺带做三件确定性的事：

- **脚注归属**：靠 `{N}----` 页标记判定——定义行必须落在引用所在页或下一页。**同一编号在书内会重排（每课从 1 开始），绝不能用编号去重**。
- **段落字母归一化**：`- A Throughout …` 与 `E The story …`（A–D 带 `- ` 前缀、E–G 不带，格式不齐）统一给出 `para_label`。
- **图片路径解析**：`![](hash.jpg)` 是**真实相对路径**，不是占位符；输出 `resolved_path` 并检查文件是否存在。

**按单元渲染给模型**（`--range` 只影响输出，块编号仍是全文件的）：

```bash
"$PYTHON_BIN" "$SKILL_ROOT/tools/split_blocks.py" "<源文件>" \
  --range <unit.start_line>:<unit.end_line> \
  --render "$WORKDIR/blocks_<unit-id>.txt" --quiet
```

渲染成 `[bid] 文本` 形式（**不含行号**），这就是模型看到的全部。

**3D-b · 切分（模型，一次调用）**

按单元循环。输入：

- 该单元的渲染块表（`[bid] 文本`）
- 该单元在结构树上的子树（节点 `id` + 标题 + `type`）
- 目录页里该单元的条目（课文标题 / 视频标题 / 技能名 / 词缀）
- 该单元的**固有标签**：课时编号（1A / 1B）与词缀（`uni-` / `-ology`）——它们藏在正文里，标题要用

指令：

```
你是教材结构编辑。把这一章切分成若干「知识点」。

切分的单位不是书里的标题层级，而是「一个学生能独立学完的知识块」。

规则：
1. 课文按主题切，不按段落等分；同一篇课文可以切成多条。
2. 相邻的同类碎片要合并（例：词汇练习 + 词缀链接 → 一条）。
3. 下列板块不单独成条：
   WARM UP / BEFORE YOU READ / CRITICAL THINKING /
   BEFORE YOU WATCH / WHILE YOU WATCH / VOCABULARY REVIEW。
   把它们写进相邻知识点的 blocks，作为该条的引入或回扣。
4. 视频课整体作为一条。
5. 只输出 blocks 的编号范围，不要输出行号，不要引用原文大段内容。
6. 标题格式：`主题 : 侧重点`。禁止「第X部分」「(一)」这类位置式命名。
   - 阅读技能页：`<技能名> (Reading Skill)`
   - 词汇页：    `Unit <课时号> Vocabulary and the <词缀> <Suffix|Prefix>`
   - 其余：      `<主题> : <这一条讲了什么>`
7. 每章产出 8–12 条。
8. 归不进任何知识点的块（纯图注、纯答案页）放进 unassigned，并说明原因。
9. 不确定某块该归哪条时，归给内容上最接近的那条，不要新开条目。
10. 块编号必须**严格递增、首尾相接**：一条的 blocks 只写成少数几段连续区间，
    且这些区间必须**排在相邻条目区间之外**——区间之间不许交错。
    （反面例子：把脚注块 [125,126] 归给第一条，却把 [123,124] 归给第二条。）
```

产出 `segments.json`：

```jsonc
{ "unit": "u01",
  "knowledge_points": [
    { "title": "The World's Game: Soccer History and Popularity",
      "blocks": [104, 105, 106, 107, 108, 109, 111, 112, 113, 114, 115, 116, 117],
      "nodes": ["u01-reada-before", "u01-reada-passage"] }
  ],
  "unassigned": [ { "blocks": [95, 96, 97], "reason": "单元扉页与配图，非知识点" } ] }
```

样例见 `tools/fixtures/example-segments-u01.json`。

**3D-c · 锚点换算与校验（合入 JSON）**

```bash
"$PYTHON_BIN" "$SKILL_ROOT/tools/build_knowledge_points.py" "<segments.json>" \
  --blocks "$OUT_DIR/blocks.json" \
  --structure "$OUT_DIR/book-structure.json" \
  --merge
```

脚本做这些事：块编号 → 行号区间；`anchor` 取**消费范围的包络**（因此起点常早于正文标题——它吃进了被吸收的热身板块）；生成 `u01-k01` 形式的 `id`；校验块编号存在、`nodes` 引用有效、同 unit 区间不重叠、锚点不越界；报告该 unit 的块覆盖率。`--merge` 写入前留 `book-structure.json.bak`，默认**替换该 unit 已有的知识点**，所以反复调参重跑是安全的。

跑完**重跑一次校验门**，看 L2-10（重叠）与 L3-09（覆盖率）。若覆盖率低，先判断漏掉的块是**有意跳过**（补 `coverage.omitted`）还是**解析丢了**（补 `coverage.gaps`）——别让它们无声地消失。

**一个可用的自检**：`sed -n '<kp.anchor.start_line>,<kp.anchor.end_line>p' "<源文件>" | head -3`。首行应当是该知识点的第一段内容（常是热身题的题号行，# 而不是正文标题——那是正常的）。

**踩过的坑（务必避开）**

- **交错区间 → L2-10 必报**。`anchor` 是包络（min/max），不是块的并集。所以「第一条吃 [125,126]、第二条吃 [123,124]」这种交错写法，
  会让第一条的包络一直延伸过第二条的起点，两条区间直接重叠。**相邻两条的块区间在数轴上不许交叉。**
  脚注块（`footnote_def`）按物理位置归给紧邻的那一条即可，不要为了「语义上属于前半篇」而回填。
- **区间不连续会触发警告，但不一定是错**。有意丢弃的块要有 `coverage.omitted` 或 `unassigned` 里的说明，
  否则脚本会逐条报「编号不连续」。
- **起点落在 `{N}----` 页码标记块上是正常的**。KP 的包络往往从印刷标题的前一页末尾开始（吃进了 WARM UP / BEFORE YOU READ）。
  这类页码标记块无正文信息，其宿主节点可能属于前一板块——这是边界现象，不影响按锚点切片，不必强行对齐。
  真正要修的是**起点落在别人的正文块上**（例如把上一节的 `Review this reading skill in Unit X` 复习题误划进下一条），
  那种情况把切点后移一个块即可。
- **切完顺手核一遍归属**：对每条 KP，取它消费的正文块（排除 `page_marker`）的宿主节点，
  看是否都出现在该条的 `nodes` 里。不一致的条目值得逐条人眼确认。

### 锚点自检（重要）

生成后随手抽一个节点验证锚点真的可用：

```bash
sed -n '<start>,<end>p' "<源文件路径>" | head -3
```

首行应当是（或包含）该节点的标题。若不对，说明锚点错了，回到 B 修——**不要指望校验器替你把关内容正确性**，它只能查结构自洽。

### Mode 2 到此结束

若用户只要结构：**结构 + 知识单元**通过校验门后停下，进 Step 10 打印简报，不做 Step 7/8。（用户显式说过「只出节点树」的，3D 也没跑，JSON 里就没有 `knowledge_points` 键。）

## Step 4 — 确认中国学生受众、用途与深度

讲义面向中国学生自学，以自然中文讲清概念、过程与依据；外语学习所需的原句、表达或专业符号保留。先采用用户或宿主任务已给出的年级、基础、目标、深度与内容限制，不重复询问已明确的信息。没有年级时以来源难度合理组织、解释必要前提，不擅自设为小学生、不假定掌握某课程，也不声称符合未经核对的中国课标。

默认采用下文的自学讲解原则，而不是给教师、研究者或开发者写材料分析报告。宿主已给深度时直接执行；独立使用且用途未明确时可问：

> 「这些材料主要拿来做什么？
> 1. **复习速览 / 检索** —— 想快速想起「这块讲了什么」
> 2. **学生学习 / 当讲义读**（默认）—— 要能直接读懂的讲解
> 3. **深入讲解 / 精读课** —— 要更细的推导、条件或语言分析，按学习目标展开」

据此定深度档 `DEPTH`：

| 档 | 单条 tokens | 面向 | 内容 |
|---|---|---|---|
| `摘要` | 约 800 | 复习、检索 | 核心内容 + 脉络 + 要点 |
| **`讲义`** | 约 3,500 | 学生学习 | 按当前学习目标讲清内容、方法及原有例子/任务（见 Step 7） |
| `精讲` | 约 7,000 | 深入学习 | 深化当前目标：数学的推导与条件、语言的句法与表达等；不自动新增无关板块 |

默认 `讲义`。Mode 3（复用结构重做材料）且用户未指定时同样默认 `讲义`。

**深度档只是运行参数，不写进 JSON**：它是 Step 7 每次调用时传给模型的档位，随时可换，改了不影响结构。命令行可整体覆盖；用户希望逐条不同档时，在 Step 7 分批跑即可（切分时不给 `depth` 字段，避免多一个状态位）。

**材料写到哪儿——这里说清楚，别和 Step 3 的产物混了**：

| | 载体 | 深度档的作用 |
|---|---|---|
| 结构 | `$OUT_DIR/book-structure.json` | 无。Step 3 就写完了，之后一个字节都不改 |
| 材料正文 | `$OUT_DIR/chapters/<kp.id>-<slug>.md`（每条 KP 一份） | **决定这些 md 的内容类型与篇幅** |
| 指回关系 | `knowledge_points[].content_file`（一个**路径字符串**） | 无 |

即：**JSON 里永远没有材料正文**，只有「这条做过没有、文件叫什么」的指针；材料是 Step 7 逐条生成的独立 md 文件。所以换档重跑 = 重写 `chapters/` 下的 md，JSON 不用动；反过来 Mode 2「只要结构」就是不跑 Step 7，`chapters/` 里什么都不出现。

`摘要` 档只保留核心结论与脉络，不展开逐题解析。`精讲` 档深化本知识点所需的解释与依据，不是把同一段话说长，更不等于所有学科都加语言点、词源或拓展。篇幅是参考，不是填充目标。

## Step 7 — 逐条生成材料

### 这些文件是什么：**生成物，不是原文副本**

`chapters/` 里的 md 是**按深度档写出来的讲义**，不是把 `blocks` 的原文搬进去。三条界线：

- **原文是输入，不是输出**：本 KP 的 `blocks` / `anchor` 切片、这一范围内的图片、脚注，全都只是喂给模型的素材。
- **讲解的语言是中文**：脉络、题解与语言点说明面向中国学生；学习目标需要的外语词语、表达和生成示范可以保留，并与原书内容区分。复制英文原文时**只引关键句**（逐字、单句 ≤ 25 词、每篇 ≤ 8 句），不出现整段课文；引用限额不是禁止语言练习所需的外语表达。
- **要原文就回读源文件**：`sed -n '<anchor.start_line>,<anchor.end_line>p' "<source.path>"`。`chapters/` 与源文件**不是互为备份**的两个副本，别指望在材料里找全文。

成品组织由**当前知识点的学习目标、受众、来源与用户范围**共同决定，Step 4 的深度档决定展开程度。先按下面的路由选写法，再应用深度；英文原文不等于英语课，题目里有 `Task` 也不等于阅读技能。

### 粒度：一份材料 = 一条知识点

**若结构里有 `knowledge_points`，就按它切**——每条 KP 一份材料，文件名与 KP 的 `id` 对应：

```
chapters/<kp.id>-<slug>.md      # 例：chapters/u01-k01-the-worlds-game.md
```

**没有知识点时**（用户跳过了 Step 3D），退回旧规则：按结构树里最深的无子节点单元一份。但优先走 KP——`nodes` 是穷尽登记的导航树，它的叶子切出来的是「书上有几个标题」，不是「学生该学几块」。

**不要按 `type` 判粒度**：`type` 只描述内容性质，不表达是哪一级。

独立模式生成后把相对路径写回 `knowledge_points[].content_file`（无 KP 时写回节点的 `content_file`），然后**重跑一次校验门**（L3-04 会检查文件真实存在，需要传 `--out-root`）。`content_file` 有值 = 这条做过，`null` = 还没做——这就是「逐条打勾」的落点。符合 Mode 3 宿主托管例外时跳过回填和全书结构/材料存在性校验，仍核对当前材料的来源、内容和输出文件。直接写最终材料，避免另外生成一份完整草稿副本。

宿主进度中的写作动作只报告当前实际工作：原文已有示例与任务允许的辅助示例按来源区别。进入来源核对或产物校验只表示开始检查；托管运行的完成、入库与计数由宿主验收和提交确认。

### 自学讲解与适量课外补充（所有学科共用）

**像一位耐心的老师陪学生读懂，而不是替专家做文本分析。** 围绕本条真实问题或观察自然开场，接着解释“这句话/这一步是什么意思、为什么这样、接下来注意什么”，让读者能顺着思路走。可克制地用“你”“我们”，在难点给一个简短停顿或提醒；不机械重复套话、卖关子、夸奖，不幼儿化，不假装学生已经回答或理解。原书要求同伴讨论时，可引导独学者先自己想一想，再看解释；不假定现场有老师或同伴。

段落之间用有依据的过渡连接，先帮助理解，再在相关处点明写法/方法。不要把“立论、举证、指代考点”等标签、逐段功能表或词表堆成整篇主体。表格用于确有价值的比较，标题说清所学内容。溯源集中在元信息头与必要注释；正文不反复穿插“行号、blocks、回捞、已读取、文件路径”等加工说明，也不省掉实质来源或必需的出处。

**范围允许时，主动选少量紧贴知识点、能帮助理解的课外知识。** 可随文解释必要背景、生活应用、类比或相关概念，让学生知道“为什么值得理解”或“和熟悉的事有什么关系”。补充是对当前内容的解释，不把讲义扩成主题文章，不填固定“拓展”板块，不为了字数另讲一课；简单或薄内容无需强加补充。

教材陈述、作者观点、课外补充和生成示范要可分辨，例如自然说明“课文这里说的是……”“补充了解一下……”。常识性解释也要准确；具体历史日期、最新数字、研究结论或健康建议只在可靠且必要时写，已有工具可以核实就核实，不确定则省略或说明限制，不杜撰权威背书、不把相关性说成因果、不把 may 等保留语气改成科学定论。不要为补充强制联网。用户禁止扩展或新增例题/练习/图片时优先服从，自学引导不等于自动增题。

### Step 7 的语言、领域与当前目标确认 → 按需加载写法

使用宿主可选进度时，只报告实际发生的讲解组织或概念处理动作；报告词表不决定模板族，也不增加模板内容。

读当前 KP 原文与必要上下文，先确认输入语言，再结合已有全书领域与本条任务确认实际学科/学习目标，随后读取匹配的 reference（路径相对本 Skill 根目录）。Mode 3 没有 Step 2.1 上下文时，此处用已提供来源补齐判断；不是重新建树或抽取。讲解始终面向 Step 4 的中国学生受众，输入中文/英文不改变这一点。

只加载当前讲义需要的写法；同批同一路径已读可复用，不自动加载所有 reference。识别和加载嵌入必要来源阅读，不新增分类 JSON、交付报告或专门规划轮次，不为选写法遍历全书。

| 当前学习目标 | 按需读取 | 不足以单独判定的信号 |
|---|---|---|
| 理解数学概念、运算、证明、量或图形关系 | `reference/material-math.md` | 英文原文、`Task`、课文形式不改变数学目标 |
| 语文阅读/写作，或英语及其他外语的阅读、听说写、语法、词汇 | `reference/material-language.md`，选匹配语言目标的部分 | 中文语文不套音标/英语词源；连续英文不自动意味着英语课 |
| 科学、历史、技术及其他领域，或领域尚不能确定 | `reference/material-general.md`，按真实领域组织 | 没有专项模板不等于没有学科，不强行归入英语模板 |

明确的混合目标只组合必要部分：如计算时长并用英语比较，读取两份 reference，讲清计算后提供所需表达；**不要拼接两份完整模板**。目标不明确时优先遵守明确用户要求与已读来源，保守组织，不猜学科强行增加练习。

**模板、深度与进度动作都不是必做清单。** 是否解释术语、设置易错点、讨论观点、承接上下条或复习，取决于当前目标和真实来源。数学精讲不自动加音标/词源，语言讲义也不自动加批判性思维。单元首末位置不要求全单元路线、词汇复习或回捞全书；只在相关且有依据时短述位置。用户禁止新增例题/练习/图片/扩展时，所有写法都服从限制。

摘要给结论与关键条件；讲义解释内容和原有例子/任务；精讲加深当前目标的依据、方法与条件，而非增加无关板块。按需 reference 不能改变输出契约、锚点、引用或宿主职责。

### 每条 KP 一次调用：要喂什么

上下文或图表动作以实际读取、解读为准：只有路径或占位信息不能声称已经读图；没有相应来源就不报告该动作。报告遵循本次任务契约和上面的可选约定。

**默认串行，但允许任意起点。** 材料必须独立可读，承接/预告不是必需段落。确需前后文时，用户可能直接点任意一条（补做、重做、跳着做），这时相邻材料不存在——不许因此拒绝、留空或写「待补充」，改用下表补必要上下文。

| 连载要素 | 正常来源 | 前文不存在时的代理来源 |
|---|---|---|
| 承接上一条 | 上一条材料的结尾文字 | **上一条 KP 的 `anchor` 原文**（取其末尾几行）+ 上一条标题 + 上一条 `blocks` 的标题清单。据此归纳「上一节讲了…」，**只归纳原文，不许引用不存在的讲法或结论** |
| 预告下一条 | 下一条标题 | 同左——标题始终能从 JSON 取到，与生成过与否无关 |
| 单元路线导览（仅单元首条） | 本单元全部 KP 的标题 | 同左；标题不足以说清位置时，再补该单元结构子树（`nodes` 层级名）与目录（TOC）条目 |
| 跨条回指 | 已生成 KP 的一行摘要 | **该 KP 的标题 + 其 `anchor` 原文摘要**；**不得虚构更早条目的结论**——只回指确实读到的内容 |

**一句话原则：讲义会缺，JSON 与源文件不会。** 前文材料不存在时，一律**降级用「原文 + 结构 + 相邻标题」重建上下文**，而不是放宽这一条本身的写法标准。

输入清单：

- 本 KP 的原文（用 `anchor` 切片；`blocks` 里的块是精确范围）
- **本范围内的图片**（多模态直读——`![](hash.jpg)` 是真实相对路径，路径可由 `blocks.json` 的 `figures[].resolved_path` 拿到）
- **上下文（按下表取，前文缺位时走代理来源）**：
  - 上一条 KP 的结尾文字，**或**其 `anchor` 原文的末尾几行
  - 下一条 KP 的**标题**（始终可得）
  - 本单元 KP 的标题列表（需要定位本条时使用，不要求逐条串讲）
  - 单元目录（TOC 条目）与该单元结构子树——补「这一块在全单元里的位置」
  - 已生成 KP 的一行摘要（**只回指确实读到的那些条**；一条都没生成时省略，别编）
- 本范围的 `footnotes[]` ——保留其对当前内容的解释、条件与来源；只有语言学习目标需要时才转为词汇讲解，不把所有脚注当词表
- `para_label` 映射（材料会用 A/B/C… 定位段落；注意 A–D 带 `- ` 前缀、E–G 不带）
- 该单元的结构子树（供结构分析引用节点）
- **邻近的「答案行」与脚注定义行**：它们常印在本条 `anchor` **之外**（页底、或下一页页首），
  但在语义上属于本条。按**题号 / 脚注编号**回捞——脚注查 `blocks.json` 的 `footnotes[]`，
  答案查源文件里的 `Answers to …` 行。只按 `anchor` 切，可能丢掉答案或脚注中的重要说明。
  引用时**在材料里注明出处行号**，免得看起来像自己编的。
  若全文件检索后**确实一处答案行都没有**，先分清是哪种情形再写 `coverage.gaps`：
  **① 原书体例**（学生版不印阅读理解答案，答案在教师用书）→ `severity: low`，写"答案不在本版内"；
  **② 解析丢失**（原书有、产物里没了）→ `severity: medium`，写"答案页缺失"。
  两者混用会让人误以为解析质量有问题——**教材类书籍的答案缺失，多半是第 ① 种。**

### 篇幅（按深度和来源密度，不是按学科模板）

| 材料 | `摘要` | `讲义` | `精讲` |
|---|---|---|---|
| 教材知识点 | 约 800 | 约 3,500 | 约 7,000 |

这是参考值，不是下限或硬上限。**密度优先于长度**：短来源和简单概念应更短，不为凑字数注水；深度加在当前学习目标上，不为达到篇幅新增题目或语言板块。

### 硬约束

- **引英文只引关键句、逐字**，单句 ≤ 25 词，每份材料 ≤ 8 句。`精讲` 档的逐句语言点**不靠整句照抄来"逐句"**：
  每句只引定位片段（≤10 词）并给行号，整句回读源文件——所以它**不占用这 8 句的额度**，8 句留给论点句 / 转折句 / 收尾句这类真正的关键句。
- **不得编造教材里的策略名或板块名**——只能引用原文实际出现的。例：`PREVIEWING` / `PREDICTING` 确实印在书上，可以引用；"批判性阅读策略"这种书里没有的标签不许造。
- 书外补充遵循上文共同原则：帮助当前理解、可靠、可辨来源，不确定不写；不能用生动叙述掩盖证据不足。
- **只处理本条 `blocks` 范围内的内容**，范围外的最多作为背景提及。
- **每条材料要独立可读**：不假设读者看过相邻条目（用户可能只挑一条看）。
- **承接与回指必须真有依据**：写「上一节提到…」「前面讲过…」时，依据只能是①**已生成的那份材料**，或②**原书对应区间的原文**。
  两者都没有时，改写成不依赖前文的说法（如「本节要解决的是…」），**绝不许编造上一条的结论**——被点单条、乱序生成时最容易犯这个错。
- 练习题干只需简述，答案必须给依据。
- 核对解释的适用条件、计算/图示/文字的一致性；不要把局部例子或原文简化表述泛化成无条件规则。需要时用现有工具核算可确定的计算；这不证明整篇讲义正确。同模型自查不是独立审阅，无法核实的内容应标明限制或省略，不声称已保证准确。
- **正文里不写 id**。跨条引用一律用**标题**（如 `《Sweet Love ②：越多越想吃，以及学校开始反击》`），
  `u01-k02` 这类 id 只允许出现在开头那段元信息头里——那是溯源区。三条理由：
  ① 跳转是**渲染层的职责**，相邻关系与 `content_file` 都能从 JSON 推出来，正文再写一遍是冗余，冗余就会双写不同步；
  ② 写成裸 `` `u01-k02` `` **不是链接**，点了不会跳，等于只付噪声的代价、不拿功能；
  ③ 讲义是给人读的，id 对读者零信息量。
  真要可跳转，就按 `knowledge_points[]` 的顺序在渲染时生成导航，别把 id 固化进正文。

### 与 Step 8 的关系

Step 8 的 `glossary` / `patterns` / `cheatsheet` 是**全书级聚合**（术语按字母序、跨章并列、出处标 `id`），**不按 KP 切**，不在 KP 这条链上。Step 7 只产出逐条材料。

### 逐份材料的元信息头

每份材料开头保留定位信息，便于回读与溯源：

```markdown
# <标题>

> 知识单元：`<kp.id>`　结构节点：`<node.id>, …`　源文件行：`<anchor.start_line>–<anchor.end_line>`
```

## Step 8 — 生成附加材料

宿主提供进度契约时，沿用可选报告约定，仅使用当前附加材料任务允许的阶段与动作。

### `glossary.md`

- 全书重要术语，按字母序
- 格式：`**术语** — 释义（<node.id>）`，出处用**节点 id**，不用「Ch N」
- 同一术语在多处出现时并列标注，便于做跨章节复现复习
- 单文件控制在 1,500 tokens 以内；超出就按词根/主题分组拆分

### `patterns.md`

- 书中所有具体方法、技法、流程、设计模式
- 格式：`## 名称` / `**何时用**：…` / `**怎么做**：…` / `**代价与限制**：…`
- 单文件控制在 2,000 tokens 以内

### `cheatsheet.md`

**这是最有价值的一层，它是推理辅助，不是关键词表。** 任何 人都能 grep 术语表；速查表要抓住作者的**判断**。按优先级收录：① **决策规则**（「当 X，就做 Y，因为 Z」）② **决策树**（两个以上分支的抉择，用嵌套列表或小表）③ **取舍矩阵**（把备选方案放在作者在意的维度上打分）④ **阈值与默认值** ⑤ **征兆与识别信号**（「看到 X，你大概已经处在 Y 状态」）。

不要收：赤裸的术语→释义（那是术语表）、散文段落（那是章节材料）。**每一行都要能帮人做决定。** 单文件控制在 1,200 tokens 以内。

## Step 10 — 清理与简报（裁剪版）

**只做两件事：清理临时目录、打印简报。** 不建软链、不生成主 `SKILL.md`、不发布。

清理**本次运行实际用的**工作目录（`metadata.json` 里的 `workdir` 字段）：

```bash
rm -rf "$WORKDIR"   # 带引号，路径可能含空格；WORKDIR 取本次运行报告的路径
```

不要删你没创建过的目录——可能另有一次抽取正在并行跑。

然后打印简报：

```
✅ 处理完成：<OUT_DIR>

📚 书籍：<书名> — <作者>
📄 源文件：<文件名>｜原始 <N> 行｜登记节点 <N> 个（最大层级 <N>）｜知识点 <N> 条（<N> 个单元）

产物：
  book-structure.json   — <N> 个节点，最大层级 <N>，锚点模式 <source_lines|workdir_lines>
                          knowledge_points：<N> 条，覆盖 <N> 个单元，块覆盖率约 <N>%
  validation-report.md  — L1 格式门 0　L2 一致性 <N>　L3 提示 <N>（L2/L3 不阻断）
  blocks.json           — <N> 个候选块（含 <N> 处图片、<N> 条脚注定义）
  chapters/             — <N> 份材料（约 <N> tokens），已回填 <N>/<N> 条 content_file
  glossary.md           — <N> 条术语
  patterns.md           — <N> 项方法
  cheatsheet.md         — 速查表
  ─────────────────────────────────────────
  合计约 <N> tokens（按需加载，不会一次性入上下文）

消费方式：
  建树       : 读 book-structure.json 的 nodes，按 children 递归；层级名称看 level_names
  知识点视图 : 读 knowledge_points，按 unit 分组；content_file 有值 = 这条材料已生成
  回读原文   : sed -n '<anchor.start_line>,<anchor.end_line>p' "<source.path>"
  挂材料     : knowledge_points[].content_file（或节点的 content_file）指向 chapters/ 下对应那份
  注意       : 锚点行号只在源文件未改动时有效；<workdir_lines 模式下锚点指向 full_text.txt，不是原文件>

⚠️ 覆盖范围：<coverage.scope>
<逐条列出 coverage.excluded / coverage.omitted / coverage.gaps，并注明 L2 / L3 报出的可疑项>
```

**必须如实报告 `coverage`。** 若结构有缺口、有节点是合成标题、某格式退化为 `workdir_lines` 锚点、知识点覆盖不到某些块，都要在这里说清，不能让使用者误以为产物是完整无误的。

**Mode 3 / Mode 4 / Mode 5 的简报要写清"动了什么"**：Mode 3 报「重做了 N 份材料」；Mode 4 报「新增 N 个节点、N 个节点区间变动、删除了 N 个节点」；Mode 5 报「unit X 的知识点从 N 条换成 M 条」。都注明备份文件位置。

**宿主托管简报**：符合 Mode 3 宿主托管例外时，只简短说明本任务已写出的文件及实际内容缺口，不复制正文，不声称已入库、已回填结构或全书完成。未创建备份就不报告备份；宿主负责最终验收和成功确认。

## 冲突与边界情况

| 情况 | 处理 |
|---|---|
| 输入本身就是 `more-to-skills` 的输出目录 | 走 Step 0 越界检查（Mode 3 / Mode 4 / Mode 5 / 整本重跑）后再动 |
| 输出目录已存在同名产物 | 明确告知将覆盖，取得确认；**不得静默覆盖** |
| 解析产物质量太差，L1 连过 3 轮 | **中断**，留 partial JSON 与失败报告，不进 Step 7/8 |
| 源文件是 PDF/DOCX 等非文本格式 | 锚点退化为 `workdir_lines`，指向 `full_text.txt`；简报里必须写明 |
| 改了树（Mode 4）之后 | 知识点里的 `nodes` 引用可能失效。重跑 3D，或至少跑一次校验门——L3-10 会报出来 |
| 图片文件不在源文件同目录 | `split_blocks.py` 的 `figures[].exist` 会是 `false`。要么把图片放到同目录，要么明说这一条的图读不到 |
| 想反复调切分粒度 | `--merge` 默认替换该 unit 的旧知识点并留 `.bak`，同一 unit 上反复重跑是安全的；别用 `--out` 手工拼 |
| 用户只点某一条生成（乱序 / 补做 / 重做） | 不必先补前文。按下「每条 KP 一次调用」的**代理来源**表取上下文：前一条用其 `anchor` 原文、位置用 TOC 与结构子树、预告用下一条标题。承接种措只依据**真读到的材料或原文** |
| 前一条材料还没生成 | 这不是错误状态，是常态（可按需生成）。**不得**用「前文待补」占位，也不得因缺上下文而降低本条标准 |

其余边界情况（多文件、只处理一部分、手工删节点、跳过低价值章节、`source_total_lines` 失配、页码体系缺失、脚注编号重排……）统一见 `SPEC.md` §11，不在这里重复。

## Quality Rules

1. **产出结构，不是书摘** —— 抓的是骨架、框架的确切命名、边界与反例，不是章节复述
2. **锚点必须可切片** —— 生成后随手 `sed` 验一次；宁可标注缺口，也不要伪造区间
3. **保真胜于好读** —— 作者的确切命名不要改写（「五问法」不等于「多问几次为什么」）；**不照抄原文**，一律综合、概括、提炼信号
4. **密度胜于完整** —— 1,000 tokens 的摘要胜于 10,000 tokens 的摘录
5. **结构登记与内容处理是两件事** —— 全书结构应完整，内容处理按用户要求
6. **如实报告覆盖范围** —— `excluded` / `omitted` / `gaps` 三分类别混用，缺口、合成标题、锚点降级都要写明
7. **节点 id 是唯一的外键** —— 材料、术语、速查表都用它指回树，不要用「第 N 章」
8. **两层视图别混** —— `nodes` 负责穷尽登记与回读（书上有什么就登什么），`knowledge_points` 负责交付粒度（学生该学几块）。不要为了凑知识点去改树，也不要指望树本身就等于交付单位
9. **坐标只由脚本产出** —— 行号、锚点、块编号一律来自 `scan_outline.py` / `split_blocks.py` / `build_knowledge_points.py`。模型只做语义判断（哪些内容归为一条），**任何一步都不许让模型直接写行号**
10. **每条都能单点** —— 任意一条知识点都可独立生成、独立阅读：前文材料不存在时用「原文 + 结构 + 相邻标题」重建上下文，既不空转，也不编造上一条说过什么
