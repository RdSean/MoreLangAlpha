# 其他学科与领域的材料写法

科学、历史、社会、技术与其他领域的知识点在没有专项 reference 时读取本文件。先确认真实领域，再按本条目标组织，不把“通用写法”当成没有学科，也不把中文/英文输入自动改成语文/英语课。沿用主 Skill 的中国学生自学语气、补充知识、来源、深度及交付规则。

## 选择真正需要的解释

| 目标 | 可选组织方式 | 注意区分 |
|---|---|---|
| 科学概念或现象 | 相关观察/问题 → 概念和条件 → 机制与原有证据/实验 → 回到原问题 | 观察与解释、相关与因果、模型与事实 |
| 历史/社会内容 | 问题与必要背景 → 来源支持的过程/变化 → 原因、影响或不同解释 → 要点 | 时间顺序与因果、史料与作者判断，不把复杂事件归为唯一原因 |
| 技术或方法 | 要解决的问题 → 必要概念 → 原有方法/实例及理由 → 条件与限制 | 原理与操作、失败与结果未知，不凭片段补出完整方案 |
| 一般非虚构 | 本条关心的问题 → 作者论点与依据 → 必要的概念/原例 → 结论与边界 | 作者主张与已确证事实，不泛化建议 |

选择与当前目标匹配的部分，不拼成一个万能大模板。学生要理解的是现象、过程或方法，不是“本文采用某种写作结构”这一元分析，除非学习目标确实包括作者写法。术语和比较表只是理解工具，不必每份都有。

摘要保留结论与必要条件；讲义解释关键关系和原有任务；精讲深化来源支持的证据、机制、论证或实例，而非增加无关领域知识。直接使用有意义的标题，不必照抄本文件的流程标签。没有实例或来源不够时讲清能确定的内容，不为模板虚构。

## 可用骨架（按需省略或合并）

```markdown
# <本条标题>

> 知识单元：`<kp.id>`　源文件行：`<start>–<end>`

<从本条问题/观察进入，说明要理解什么>

## <概念、现象或过程的具体标题>
<顺着来源讲清内容与关系，必要时解释术语>

## <如何理解原例/任务，或为什么会这样>
<来源中的依据、方法或例子，以及适用条件>

<简短回扣本条问题与可带走的要点；确需关联时用真实标题>
```

共通的自学语气与课外补充规则以主 Skill 为准，不额外扩展用户范围。事实不确定时不写成定论；教材简化表述与较严谨解释的差异应说明，不以文风改善替代准确性。
